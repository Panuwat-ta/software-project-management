รายงาน Phase 2 — ออกแบบและตั้งต้นทุนฐาน (W5–W7)

ข้อมูลทั้งหมดเป็นข้อมูลสมมติเพื่อการเรียน ไม่ใช่ข้อมูลลูกค้าจริง

1. ภาพรวมเฟส

รายการ ค่า
Sprint ที่ครอบคลุม Sprint 2 (Jira ID 82, closed)
สัปดาห์ 5–7
Issues SPM-11…SPM-14 (13 SP) ปิดครบ
ผลลัพธ์หลัก สถาปัตยกรรม To-Be + Cost Baseline 18,823 THB + เกณฑ์คุมงบ

เฟสนี้ทำหน้าที่ "วางแผนก่อนลงมือ" เพื่อไม่ให้การพัฒนาที่จะเกิดขึ้นในเฟสถัดไป เกิด scope creep และงบบานปลาย

3. ผลลัพธ์หลัก

ด้าน ผลลัพธ์
สถาปัตยกรรม ออกแบบ To-Be ที่รองรับ SQLite, สมาชิก 4 ระดับ และ checkout โดยไม่แตะ UI
คุณภาพ กำหนดเป้าหมาย v(G) ≤ 8, CBO ≤ 4, DIT ≤ 2, Coverage ≥ 85%
งบประมาณ แรงงาน 15,000 + โครงสร้างพื้นฐาน 1,000 + สำรอง 2,823 = 18,823 THB
การควบคุม เกณฑ์แจ้งเตือนผลต่างงบ ±5% / 5–10% / >10%
กระบวนการ Communication Matrix, DoR 4 ข้อ, DoD 4 ข้อ

หมายเหตุ: ตัวเลขงบของ W5 (39,100 THB) เป็นคนละฐานกับ baseline ที่อนุมัติใน W7 ต้องระบุฐานทุกครั้งที่อ้างอิง

4. ปัญหาที่พบและการจัดการ

ปัญหา การจัดการ
ต้นทุนแฝงของการย้ายฐานข้อมูลไม่ถูกประมาณ วิเคราะห์ Cost Variance และเพิ่มเงินสำรอง 15%
ความจุทีม 36 ชั่วโมงต่ำกว่างานจริง ตั้งกติกาคุมงานเข้าสปรินต์และใช้ Velocity จริงเป็นเกณฑ์

5. ผลงานที่ส่งต่อให้เฟสถัดไป

  • แบบออกแบบ SQLite/Member ถูกพัฒนาจริงใน Sprint 5 ตามเส้นทางนี้
  • เกณฑ์คุมงบใช้ติดตามตลอด Sprint 3–5 (บันทึกใน week-9 และ week-12)
