Team Communication Matrix

ตารางการสื่อสารและการประสานงานภายในทีม

กำหนดช่องทาง ความถี่ และผู้รับผิดชอบตามกรอบ RACI เพื่อควบคุมจังหวะการทำงาน

อัปเดตงานประจำวัน Daily
  • ช่องทาง: Discord Voice / กลุ่มแชท
  • ความถี่: ทุกเย็น (15 นาที)
  • ผู้รับผิดชอบ: Project Manager
  • ติดตามความก้าวหน้าและปลดล็อกปัญหาอุปสรรค
การแจ้งข้อผิดพลาด Bug Report
  • ช่องทาง: การ์ดงานบนบอร์ด Trello
  • ความถี่: ทันทีที่พบข้อผิดพลาด
  • ผู้รับผิดชอบ: QA / Tester
  • ส่งข้อมูลให้ผู้พัฒนาแก้ไขได้อย่างทันท่วงที
การตรวจทานโค้ด Code Review
  • ช่องทาง: GitHub Pull Request
  • ความถี่: เมื่อสร้าง PR เสร็จสิ้น
  • ผู้รับผิดชอบ: Tech Lead
  • ตรวจสอบความสะอาดตามมาตรฐาน PEP 8

Definition of Ready & Done

เกณฑ์ความพร้อม (DoR) และเกณฑ์ความสำเร็จ (DoD)

ข้อกำหนดก่อนเริ่มลงมือพัฒนา และเกณฑ์การส่งมอบเพื่ออนุมัติปิดงานเข้าช่อง Done

Definition of Ready (DoR) ก่อนเริ่มงาน
  • การ์ดงานระบุรายละเอียด (Description) ของฟีเจอร์อย่างชัดเจน
  • มีการประเมินจุดเสี่ยง (Hotspot) เพื่อระบุส่วนกระทบของระบบ
  • ระบุบทบาทชัดเจนใน RACI Matrix ว่าใครคือ R และใครคือ A
  • สร้าง Branch แยกบน GitHub ออกจากกิ่ง develop เรียบร้อย
Definition of Done (DoD) ก่อนปิดงาน
  • ผ่านการตรวจสอบ Code Review โดย Tech Lead ตามมาตรฐาน PEP 8
  • ผ่านชุดทดสอบอัตโนมัติ (Automated Tests) ด้วย PyTest ครบ 100%
  • รวมโค้ด (Merge) เข้าสู่กิ่งหลักในระบบจัดการเวอร์ชันสำเร็จ
  • จัดทำเอกสารสรุปผลการทดสอบและบันทึกอัปเดตบน Trello
