Charter ตั้ง 4 เป้าหลักคุมทิศทางปรับโครงสร้าง

ที่มา: Project-Charter.md หมวด 2

  • เสถียรภาพทนต่อข้อมูลผิด ไม่ล่มเมื่อกรอกผิดชนิด
  • ปรับโครงสร้างยุบโค้ดซ้ำ แยกโมดูล เลิกใช้ global
  • ข้อมูลสมบูรณ์บันทึก JSON ปลอดภัย ไม่หายเมื่อขัดข้อง
  • ทดสอบอัตโนมัติกัน regression เมื่อแก้โค้ดเดิม

ขอบเขตชัด: ทำ 4 อย่าง เว้น GUI และฐานข้อมูลนอก

ที่มา: Project-Charter.md หมวด 3 ขอบเขตระดับสูง

ประเภทรายการ
ทำ: ตรวจรับข้อมูลดักชนิดข้อมูล ราคาและจำนวนติดลบ
ทำ: ปรับโครงสร้างเปลี่ยนชื่อตัวแปร แยกชั้นแสดงผล ยุบบล็อกซ้ำ
ทำ: บันทึกปลอดภัยเขียนไฟล์ชั่วคราวก่อนย้ายทับ (atomic)
ทำ: ชุดทดสอบunit test มูลค่าคลังและตัดสต็อก
ไม่ทำ: หน้าจอใหม่คง CLI ไม่ทำ GUI หรือเว็บ
ไม่ทำ: ฐานข้อมูลนอกคง JSON ไฟล์เดียว ไม่ต่อ SQL หรือ NoSQL
ไม่ทำ: โมดูลนอกสต็อกไม่ทำสมาชิก โปรโมชัน ชำระเงินออนไลน์

โค้ดเดิมรัน 5 เมนูบน Python ล้วนกับ JSON ไฟล์เดียว

ที่มา: doc.md รายงานเข้าใจระบบ — Python ล้วน ไม่ใช้เฟรมเวิร์ก เก็บ JSON ไฟล์เดียว (data.json)

เมนูหน้าที่
1 Show allแสดงสินค้าทั้งหมดพร้อมราคาและหมวด
2 Add or Updateเพิ่มหรือเขียนทับสินค้าแล้วบันทึกทันที
3 Outตัดสต็อก เตือนด่วนเมื่อเหลือน้อยกว่า 5 ชิ้น
4 Check Checkสรุปจำนวนชนิด มูลค่ารวม เตือนต่ำกว่า 10 ชิ้น
5 Exitออกจากโปรแกรม

บอร์ด Trello กระจาย 10 งานพร้อมผู้รับผิดชอบแล้ว

ที่มา: trello.md บอร์ดละเอียดพร้อมผู้รับผิดชอบ

หมวดงานผู้รับผิดชอบ
ปรับโครงสร้างTASK-01–03 เปลี่ยนชื่อ ยุบซ้ำ แยกโมดูลTech Lead / Developer
เสถียรภาพTASK-04–06 ดัก input กันติดลบ เซฟปลอดภัยDeveloper
ทดสอบTASK-07 เขียน unit test ตัดสต็อกและสรุปยอดQA / Tester
กำลังทำTASK-08 เตรียมสภาพแวดล้อมและมาตรฐานทีมทั้งทีม
เสร็จแล้วTASK-09–10 ทบทวนโค้ดเดิม ร่างกฎบัตรทั้งทีม

กลิ่นโค้ด 3 จุดพร้อมส่งต่อให้สัปดาห์ที่ 2 วิเคราะห์

กฎบัตรและผลทบทวนพร้อมเป็นฐานงานวิเคราะห์ต่อ

  1. ส่งต่อกลิ่นโค้ด 3 จุด (ชื่อกำกวม เงื่อนไขซ้ำ global x) ไปวาด DFD และชี้ hotspot
  2. QA เขียนเทสต์พฤติกรรมเดิมก่อนแตะโครงสร้างหลัก
  3. เริ่มงานบอร์ดหมวดปรับโครงสร้างภายใต้ขอบเขตที่ตกลง
