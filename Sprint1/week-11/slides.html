System Hardening, Atomic Writes, ตัวชี้วัดการไหลของงาน และข้อตกลง Scope Freeze Agreement

วิศวกรรมความแข็งแกร่ง (System Hardening)
  • กำจัด Code Smells 3 รายการ: Duplicate Code, Dead Code, และ Feature Envy
  • ป้องกันไฟล์พังขนาด 0 Bytes ด้วย Safe Atomic File Writing (2 จังหวะ)
  • รักษา Exception Hygiene โดยห้ามใช้ except: pass ครอบจักรวาล
การควบคุมขอบเขตและการไหล (Flow & Freeze)
  • ตรวจวัดคอขวดบนบอร์ดงานด้วย Little's Law และตั้ง WIP Limits ช่อง Review 3 ใบ
  • แช่แข็งขอบเขตที่ 29 Story Points (ส่งมอบแล้ว 27 pts หรือ 93%)
  • บังคับใช้วินัย Code Freeze เตรียมความพร้อมสำหรับการทดสอบ UAT ในสัปดาห์ที่ 12

HARDENING & QUALITY ข้อมูลสมมติเพื่อการเรียน

กำจัดกลิ่นโค้ดและสร้างความแข็งแกร่งของระบบ

การปรับปรุงเชิงวิศวกรรมตามหลัก Clean Architecture และมาตรฐาน ISO/IEC 25010

การแก้ไข Code Smells 3 รายการ
  • 1. Duplicate Code: ยุบตรรกะเช็คสินค้าซ้ำซ้อนเป็น Helper Method ใน InventoryService
  • 2. Dead Code: ลบฟังก์ชันทดลอง ตัวแปรที่ไม่ได้ใช้ และบล็อกคอมเมนต์เก่าทิ้งเด็ดขาด
  • 3. Feature Envy: ย้ายตรรกะคำนวณราคาที่คลาสอื่นดึงไปทำ กลับเข้าสู่คลาสเจ้าของข้อมูล
Safe Atomic Write & ข้อยกเว้น
  • 2 จังหวะปลอดภัย: เขียนลง .tmp จนเสร็จ แล้วใช้ os.replace() สลับไฟล์ระดับ OS
  • Zero Data Loss: ป้องกันไฟล์เสียหายขนาด 0 Bytes แม้ไฟดับหรือโปรแกรม Crash
  • Exception Hygiene: ระบุ Error เจาะจง เช่น FileNotFoundError, JSONDecodeError
  • ผลตรวจเครื่องมือ: Bandit สะอาด (Clean) ส่วน Flake8 ยังเปิดสถานะหนี้เทคนิค E501

การคุมคอขวดด้วย Little's Law
  • แผนภูมิ CFD ชี้แถบ Code Review กว้างผิดปกติสะท้อนจุดอุดตันของงาน
  • จำกัดโควตางานช่อง Review ไม่เกิน 3 ใบ หากเต็มทุกคนต้องช่วยกันตรวจ PR
  • ช่วยลด Cycle Time และทำให้การไหลของงานกลับสู่สภาวะปกติ
ข้อตกลง Scope Freeze Agreement
  • ล็อกขอบเขตที่ 29 Story Points ห้ามแตก Feature Branch ใหม่ในโค้งสุดท้าย
  • งานที่อนุญาต: แก้บั๊กวิกฤต, อุดช่องโหว่ความปลอดภัย และเพิ่ม Unit Test
