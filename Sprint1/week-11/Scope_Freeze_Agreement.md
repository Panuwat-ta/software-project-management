# ข้อตกลงการแช่แข็งขอบเขต (Scope Freeze Agreement) — สัปดาห์ที่ 11

> ที่มาทุกข้อ: บทถอดความ Week 11 — ENGSE202 (Scope Freeze + UAT) ผูกกับ ENGSE225 (Code Freeze) มีผลตั้งแต่ Hardening สัปดาห์ที่ 11

## 1. เงื่อนไขการแช่แข็ง (Freeze Terms)

1. ล็อกขอบเขต (Scope) ไว้ที่ **29 สตอรีพอยต์** (แผนเดิม 20 + CR-01 Barcode 5 + CR-02 CSV Export 4) ห้ามเพิ่มฟีเจอร์ใหม่หรือเปลี่ยนข้อกำหนดในรีลีสปัจจุบัน
2. สัปดาห์ที่ 12 (Sprint 3) เป็นช่วงเวลาแห่งความนิ่ง มุ่งเฉพาะ UAT และเตรียม Release Notes เท่านั้น
3. งานที่อนุญาตช่วง Freeze: แก้บั๊กวิกฤต (Critical Defects) อุดช่องโหว่ตามรายงาน Bandit/Flake8 และเขียน Unit Test เพิ่มเพื่อยกระดับ Coverage (ตามกฎ Code Freeze ISO 12207)
4. ห้าม: แตก Branch ฟีเจอร์ใหม่ ปรับ UI เพื่อความสวยงาม รับ Change Request ตัวใหม่ — เพราะการแก้โค้ดนาทีสุดท้ายคือสาเหตุอันดับ 1 ที่ทำให้ระบบพังวันส่งมอบ

## 2. แบบฟอร์มตรวจรับ UAT (Acceptance Protocol)

- **System Testing (ENGSE225):** ทดสอบเชิงเทคนิคว่าโค้ดทำงานถูกต้องตามสเปก — รัน PyTest Full Suite 100% Pass สแกนช่องโหว่
- **UAT Testing (ENGSE202):** ทดสอบความพึงพอใจการใช้งานจริงว่าซอฟต์แวร์แก้ปัญหาธุรกิจได้จริง — ตรวจความถูกต้องของข้อมูลรายงาน CSV

| UAT ID | สถานการณ์ทดสอบ (Business Scenario) | เกณฑ์ตัดสิน | สถานะตรวจรับ |
|---|---|---|---|
| UAT-01 | เพิ่มสินค้าใหม่พร้อมระบุ Barcode และ Reorder Point | บันทึกสำเร็จ ไร้ Crash | Passed  |
| UAT-02 | ตัดสต็อกสินค้าจนต่ำกว่าเกณฑ์ และตรวจการแจ้งเตือน | ขึ้น Alert ชัดเจน | Passed  |
| UAT-03 | ส่งออกรายงาน CSV และเปิดตรวจไฟล์ใน Microsoft Excel | Header/Data ถูกต้อง | Passed  |

โครงแบบฟอร์มเตรียมไว้: ฟีเจอร์ → ขั้นตอน → ผลที่คาดหวัง → ผ่าน/ไม่ผ่าน → ลายเซ็น

## 3. เกณฑ์เข้าทดสอบ UAT (UAT Entry Criteria)

- งาน 27/29 พอยต์อยู่ในสถานะ Done และสาธิตได้ (CR-01 ครบ 100% ส่วน CR-02 เหลือ 2 pts เป็นช่องว่างที่ทราบแล้ว)
- ผ่าน Hardening แล้ว: Atomic Writes, ไม่มี `except` แบบเปลือย, ลบ Dead Code แล้ว
- รัน Flake8 + Bandit แล้วและล้างข้อที่พบหมด (แปะผลคำสั่งจริงในบันทึกการปล่อยรีลีส)
- ชุดทดสอบผ่านทั้งหมด เตรียมแบบฟอร์ม UAT แล้ว

## 4. ขั้นตอนการเจรจา + เส้นทางเปลี่ยนแปลง → แบ็กล็อก v3.0

1. โชว์ Burnup Chart ยืนยันว่าส่งมอบ CR-01 และ CR-02 สำเร็จ (27/29 Points, 93%)
2. ชี้แจงความเสี่ยงหากเพิ่มฟังก์ชันใหม่ในโค้งสุดท้าย (ช่วง High Anxiety Period ก่อนส่งมอบ)
3. ยื่นเอกสาร Scope Freeze Agreement ให้อาจารย์ (Sponsor) ลงนามยืนยันว่าไม่มีฟังก์ชันใหม่ในสัปดาห์ที่ 12
4. หากลูกค้ามีไอเดียใหม่: บันทึกไว้ใน Future Backlog (สำหรับ Version 3.0) โดยไม่แตะต้องสปรินต์ปัจจุบัน ประเมินเป็นพอยต์ใหม่และวาง Baselines ใหม่สำหรับ v3.0
5. การแช่แข็งมีผลจนกว่าจะลงนาม UAT จะยกเลิกได้ต่อเมื่อทีม + อาจารย์ตกลงเป็นลายลักษณ์อักษรเท่านั้น
