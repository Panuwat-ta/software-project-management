สัปดาห์ที่ 11: การปรับโค้ดให้แข็งแกร่ง (Hardening) และการแช่แข็งขอบเขต (Scope Freeze)

รายงานผลการปรับปรุงความแข็งแกร่งของระบบ (System Hardening), สุขอนามัยของโค้ดและข้อยกเว้น, การสแกนเครื่องมือ และข้อตกลง Scope Freeze

เปิดสไลด์ประกอบสัปดาห์ 11 →

1. รายงานการปรับโค้ดให้แข็งแกร่ง (Hardening Report)

ดำเนินการแก้ไขกลิ่นโค้ด (Code Smells) สำคัญ 3 รายการตามหลัก Clean Architecture:

  • 1. Duplicate Code: ตรรกะตรวจเช็ค if product_id in products: ที่ซ้ำซ้อนในหลายจุด ถูกยุบเป็น Helper Method กลางใน InventoryService
  • 2. Dead Code: ลบโค้ดทดลอง ตัวแปรชั่วคราว และบล็อกคอมเมนต์ที่ไม่ใช้งานทิ้งทั้งหมดเพื่อลดภาระทางความคิด (Cognitive Load)
  • 3. Feature Envy: ย้ายตรรกะการคำนวณราคาและมูลค่าที่คลาสอื่นแอบดึงไปคิดเอง กลับเข้ามาอยู่ในคลาสเจ้าของข้อมูล (Data Owner) ตามหลัก Information Hiding

2. การเขียนไฟล์แบบอะตอมมิกและสุขอนามัยของข้อยกเว้น (Exception Hygiene)

  • Safe Atomic Write: เปลี่ยนจากการใช้ open(..., 'w') ตรงๆ มาเป็นขั้นตอน 2 จังหวะ: 1) เขียนลงไฟล์ชั่วคราว .tmp จนสมบูรณ์ 2) ใช้ os.replace() สลับไฟล์ในระดับ OS ป้องกันปัญหาไฟล์พังขนาด 0 bytes เมื่อเกิดไฟดับ
  • Exception Hygiene: บังคับห้ามใช้ except: pass ครอบจักรวาลโดยเด็ดขาด ให้ระบุประเภทข้อยกเว้นอย่างเจาะจง (FileNotFoundError, JSONDecodeError)

3. ผลการสแกนความปลอดภัยและหนี้เทคนิค (Flake8 / Bandit)

เครื่องมือสแกน สถานะการตรวจ ผลลัพธ์และข้อสังเกต
Bandit Security Scanner CLEAN ไม่พบช่องโหว่ความปลอดภัยระดับ Medium หรือ High ไม่มีการ Hardcode รหัสผ่านหรือคำสั่งอันตราย
Flake8 Linter E501 OPEN ยังพบรายการแจ้งเตือน Line too long (E501) คงค้างอยู่ จัดเป็นหนี้ทางเทคนิค (Technical Debt) ที่ต้องเก็บกวาดในรอบถัดไป

4. ข้อตกลงการแช่แข็งขอบเขต (Scope Freeze Agreement)

AGREEMENT
เงื่อนไขการแช่แข็งระบบ (Scope Freeze):
• ล็อกขอบเขตของโครงการไว้ที่ 29 สตอรีพอยต์ (แผนเดิม 20 + CR-01 Barcode 5 + CR-02 CSV 4) โดยส่งมอบแล้ว 27/29 พอยต์ (93%)
• ห้ามแตก Feature Branch ใหม่ หรือปรับแต่ง UI เพื่อความสวยงามส่วนตัว ให้โฟกัสเฉพาะการทดสอบ UAT, อุดช่องโหว่ และจัดเตรียมเอกสาร Release Notes
• ไอเดียฟังก์ชันใหม่ๆ ของลูกค้าให้บันทึกลง Future Backlog สำหรับ Version 3.0 เท่านั้น
