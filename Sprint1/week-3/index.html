สัปดาห์ที่ 3: ขั้นลงมือพัฒนาโค้ดใหม่ (Implementation & Testing Setup)

พัฒนาโค้ดฉบับปรับปรุง app_v2.py ตาม Blueprint กำหนดเกณฑ์ความสำเร็จ Definition of Done (DoD) และจัดทำตาราง RACI Matrix

เปิดสไลด์ประกอบสัปดาห์ 3 →

1. เกณฑ์ความสำเร็จของชิ้นงาน (Definition of Done - DoD)

เอกสาร dod.md ระบุข้อตกลงและมาตรฐานของกลุ่ม ชิ้นงานย่อยจะถือว่าเสร็จสมบูรณ์เมื่อผ่านเกณฑ์ครบทุกข้อ:

  • 1. ผ่านการทดสอบอัตโนมัติ 100% (PyTest Passed): โค้ดใหม่ต้องรันผ่านชุดทดสอบทั้งหมด ไฟเขียวครบทุกเคส และสามารถบันทึกรายงานลง test.json ได้ถูกต้อง
  • 2. เขียนโค้ดตามมาตรฐานการออกแบบ (Code Standards): ปรับโครงสร้างเป็นแบบ OOP ตาม Blueprint และตั้งชื่อตัวแปร ฟังก์ชัน คลาสตามมาตรฐาน PEP 8
  • 3. ความปลอดภัยและดักจับข้อผิดพลาด (Error Handling & Integrity): มีระบบดักจับข้อผิดพลาดจากฝั่งผู้ใช้ไม่ให้แอปพลิเคชันล่ม และใช้กลไก Atomic Save (os.replace) ในการบันทึกข้อมูล
  • 4. อัปเดตเอกสารคู่มือครบถ้วน (Documentation Updated): อธิบายการทำงานใน Docstring และอัปเดตเอกสาร Markdown ให้สอดคล้องกัน
  • 5. ผ่านการรีวิวและอนุมัติ (Code Review & Approval): QA ทดสอบควบคู่กับระบบแมนนวลไม่พบ Critical Bug และได้รับการกด Approve จาก Tech Lead

2. ตารางกำหนดบทบาทหน้าที่ (RACI Matrix)

อ้างอิงจาก raci.md สำหรับชิ้นงานย่อยในการวิวัฒนาการระบบ:

ชิ้นงานย่อย (Task) ภานุวัฒน์ (PM/Dev) เอกพันธ์ (QA/Tester) ณฐภาพ (Tech Lead)
1. เขียนโค้ดแก้บั๊ก Choice 2 (Add/Update) R (ผู้ปฏิบัติงาน) C (ผู้ให้คำปรึกษา) A (ผู้อนุมัติ)
2. ปรับโครงสร้างโค้ดเป็นแบบ OOP/MVC R (ผู้ปฏิบัติงาน) I (ผู้รับทราบ) A (ผู้อนุมัติ)
3. กด Approve รวมสายโค้ดเข้าคลังหลัก (Merge) I (ผู้รับทราบ) I (ผู้รับทราบ) R, A (ตรวจและอนุมัติ)
4. พัฒนาสคริปต์ Automated Test (PyTest) C (ผู้ให้คำปรึกษา) R (ผู้ปฏิบัติงาน) A (ผู้อนุมัติ)
5. เปลี่ยนผ่านระบบฐานข้อมูลเป็น SQLite R (ผู้ปฏิบัติงาน) C (ผู้ให้คำปรึกษา) A (ผู้อนุมัติ)
6. เพิ่มฟีเจอร์ระบบสมาชิก (Member Discount) R (ผู้ปฏิบัติงาน) C (ผู้ให้คำปรึกษา) A (ผู้อนุมัติ)

3. สถาปัตยกรรมโค้ด app_v2.py

ในสัปดาห์นี้ โค้ดได้รับการปรับปรุงสู่ app_v2.py โดยยกเลิกการใช้ global x และแทนที่ด้วย 3 คลาสหลัก:

  • class Product: ห่อหุ้มข้อมูลสินค้า (ID, Name, Quantity, Price, Category) รองรับเมธอด to_dict() และ from_dict() พร้อม Fallback
  • class InventoryManager: บริหารจัดการสต็อกสินค้าในหน่วยความจำ มีเมธอด add_or_update_product(), cut_stock(), get_total_inventory_value() และเซฟไฟล์ผ่านไฟล์ชั่วคราวด้วย os.replace
  • class InventoryCLI: ชั้นแสดงผลเมนูและรับข้อมูลพร้อมระบบตรวจสอบความถูกต้อง (Input Validation)
