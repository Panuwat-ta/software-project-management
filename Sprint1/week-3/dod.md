# Definition of Done (DoD) - เกณฑ์ความสำเร็จของชิ้นงาน

เอกสารนี้ระบุข้อตกลงและมาตรฐานของกลุ่ม สำหรับใช้ตรวจสอบว่าชิ้นงานย่อย (Task) แต่ละชิ้น "เสร็จสมบูรณ์" พร้อมส่งมอบและรวมเข้ากับคลังโค้ดหลัก (Main Repository) อย่างแท้จริงหรือไม่ ชิ้นงานจะถูกพิจารณาว่าเสร็จสมบูรณ์ก็ต่อเมื่อผ่านเกณฑ์ **ทุกข้อ** ดังต่อไปนี้:

---

## รายการตรวจสอบความสำเร็จ (DoD Checklist)

- [x] **1. ผ่านการทดสอบอัตโนมัติ 100% (PyTest Passed) [สำคัญมาก]**
  * โค้ดที่เขียนขึ้นใหม่หรือถูกแก้ไข จะต้องรันผ่านชุดทดสอบ **PyTest** ทั้งหมด
  * ผลการรันทดสอบหน้าจอต้องขึ้นเป็น **ไฟเขียว (PASSED)** ครบทุกเคส โดยไม่มีแจ้งเตือน FAIL หรือ ERROR
  * ระบบจะต้องสามารถออกรายงานผลการรันทดสอบและเซฟลงไฟล์ `test.json` ได้อย่างถูกต้อง

- [x] **2. โค้ดเขียนตามมาตรฐานการออกแบบ (Code Standards)**
  * ปรับโครงสร้างโค้ดเป็นรูปแบบ Object-Oriented Programming (OOP) ตาม Blueprint อย่างถูกต้อง
  * ตั้งชื่อตัวแปร ฟังก์ชัน และคลาสตามมาตรฐาน PEP 8 (ตัวแปรสื่อความหมายชัดเจน ไม่อักษรย่อตัวเดียว)

- [x] **3. ความปลอดภัยและดักจับข้อผิดพลาด (Error Handling & Data Integrity)**
  * มีการดักจับข้อผิดพลาดที่เกิดจากฝั่งผู้ใช้ (เช่น กรอกตัวหนังสือลงในช่องตัวเลข) ไม่ให้โปรแกรม Crash
  * กระบวนการบันทึกข้อมูลต้องปลอดภัย เช่น การใช้กลไก Atomic Save (`os.replace`) หรือการใช้พารามิเตอร์ป้องกัน SQL Injection ใน SQLite

- [x] **4. อัปเดตเอกสารคู่มือครบถ้วน (Documentation Updated)**
  * มีการอธิบายการทำงานของคลาสหรือฟังก์ชันใหม่ๆ ไว้ใน Docstring
  * เอกสาร Markdown ที่เกี่ยวข้องกับฟีเจอร์นั้นๆ ถูกอัปเดตให้เป็นปัจจุบัน

- [x] **5. ผ่านการรีวิวและการอนุมัติ (Code Review & Approval)**
  * ซอร์สโค้ดต้องถูกส่งให้ QA (เอกพันธ์) ทำการทดสอบควบคู่กับระบบแมนนวลและไม่พบ Critical Bug
  * โค้ดทั้งหมดต้องได้รับการรีวิวและถูกกด **Approve** จาก Tech Lead (ณฐภาพ) ผู้มีอำนาจ Accountable ของโปรเจกต์ก่อนจึงจะรวมเข้าคลังหลักได้
