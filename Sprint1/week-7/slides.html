เส้นฐานงบประมาณ ความจุทีม และคุณภาพ ISO 14598

การอนุมัติเส้นฐานต้นทุน (Cost Baseline), การวางแผนความจุใน Sprint 1 และการตั้งเป้าหมายคุณภาพเชิงปริมาณ (ตัวเลขจำลองเพื่อการศึกษา)

สาระสำคัญประจำสัปดาห์
  • อนุมัติเส้นฐานงบประมาณโครงการรวม 18,823 บาท (ตัวเลขจำลองเพื่อการศึกษา) พร้อมกำหนดเกณฑ์เฝ้าระวังผลต่าง
  • คำนวณความจุการทำงานของทีม 3 คนในรอบ 2 สัปดาห์ รวมเป็น 36 Man-Hours
  • กำหนดเป้าหมายดัชนีชี้วัดคุณภาพตาม ISO/IEC 14598 และวางท่อส่ง CI/CD Quality Gate

เป้าหมายคุณภาพตาม ISO/IEC 14598

เกณฑ์เป้าหมายสำหรับยกระดับจาก legacy code — ไม่ใช่ผลยืนยันว่าทำได้ครบแล้ว

Maintainability และ Reliability
  • Cyclomatic Complexity เป้าหมาย ≤ 8
  • ยกเลิก global state 100% และใช้ Class Instances
  • Code Coverage เป้าหมาย ≥ 85%
Security และ CI
  • Input Validation ด้วย try-except
  • SQLite ในอนาคตต้องใช้ parameterized query 100%
  • คุณภาพต้องผ่าน pytest ก่อน merge

การจัดสรรงบประมาณที่อนุมัติ
ค่าแรงทางตรง (งาน Refactoring + ทดสอบ) 15,000 บาท (80.0%)
โครงสร้างพื้นฐานและเครื่องมือ (Cloud & Services) 1,000 บาท (5.0%)

ความจุทีมและ Quality Gate ก่อนรวมโค้ด

ใช้ความจุเป็นเพดานของ Sprint และใช้ CI เป็นด่านกันโค้ดที่ยังไม่ผ่านทดสอบ

Capacity Planning
  • ทีม 3 คน × 6 ชม. × 2 สัปดาห์ = 36 Man-Hours
  • ห้ามรับงานเกินความจุที่วางไว้
  • เกณฑ์งบ: 0–5% ปกติ, 5–10% เตือน, >10% ทบทวน scope
Quality Gate
  • GitHub Actions ติดตั้ง pytest==8.0.2 จาก requirements.txt
  • รัน test_app.py ทุก Pull Request
  • เทสต์ไม่ผ่าน: ห้าม merge จน Tech Lead ตรวจผ่าน
