ข้อเสนอโครงการฉบับสมบูรณ์ (Integrated Planning Proposal)

รวบรวมงานสัปดาห์ที่ 1–4 เป็นข้อเสนอปรับปรุงระบบจัดการคลังสินค้า CLI: เป้าหมาย 4 ด้าน ขอบเขต 4 เฟส ตารางเวลา เมทริกซ์ความเสี่ยง DFD และเกราะ PyTest

เปิดสไลด์ Phase 1 →

1. เป้าหมายโครงการและขอบเขต 4 เฟส

  • Stability: ทนทานต่อข้อผิดพลาด ไม่พังจาก input ผิด (Crash Prevention)
  • Refactoring: ยุบโค้ดซ้ำ แยกฟังก์ชันเป็นโมดูลชัดเจน
  • Data Integrity: เซฟ JSON ปลอดภัย กันข้อมูลหาย
  • Automated Testing: regression tests กันแก้แล้วพังของเดิม
  • เฟส 1 Refactoring & Infrastructure: แยก members.json เลิก global ใช้ Class ยุบตรรกะซ้ำ
  • เฟส 2 Member Database: โมเดลสมาชิก + LOAD/SAVE + Safe Atomic Write
  • เฟส 3 Discount & Checkout: ตรรกะส่วนลด + รายละเอียดคิดเงินก่อนหักสต็อก
  • เฟส 4 Exception & QA: ดัก input แปลก + Graceful Degradation + Unit Tests

2. ตารางเวลาและ Trello

สัปดาห์ เฟส งานหลัก สถานะ Trello
1 Phase 1 วิเคราะห์โค้ดเดิม + Charter + Scope Backlog / To Do
2 Phase 2 DFD + เสี่ยงระบบ + แผนเลิก Global Done
3 Phase 3 โค้ดจัดการสินค้า + Exception Handling Done / Review
4 Phase 4 PyTest + เล่ม Proposal Done

หมายเหตุ: "เฟส" คืองานสาย (workstream) ไม่ใช่เลขสัปดาห์ ตารางนี้แมปตาม proposal ต้นฉบับ

3. เมทริกซ์ความเสี่ยง 4 ข้อ

# ความเสี่ยง มาตรการ
1 Global State Conflict (global x เขียนทับกัน) แปลงเป็น OOP แยก Business Logic จาก CLI
2 Data Corruption (dump ทับตรงแล้วไฟดับ) Atomic Write / SQLite Transaction
3 Input Type Mismatch (ValueError แล้วล่ม) Validation + try-except เคร่งครัด
4 Encoding ภาษาไทยเพี้ยนข้าม OS บังคับ UTF-8 ทุกจุดอ่าน/เขียน

4. DFD และเกราะ PyTest

DFD Level 1 กระบวนการ P1–P6: load → show_all → add_update → cut_stock → check → save ผ่าน store กลาง x (หน่วยความจำ) และ data.json (ดิสก์) โดยมี save เป็น Safe Save จุดเดียว

เกราะ regression ตัวอย่าง: cut_stock("1", 5) → remaining 15 · เบิกเกินสต็อกต้อง success False · ID ไม่มีต้อง Product not found!
