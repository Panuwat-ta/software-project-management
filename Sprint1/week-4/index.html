สัปดาห์ที่ 4: การทดสอบและการแก้ไขปรับปรุงโค้ด (Testing & Code Refinement)

สอบทานความถูกต้องของระบบด้วยการทดสอบอัตโนมัติ (Automated Unit Testing), ส่งออกผลทดสอบลง test.json และปรับแต่งโค้ดเวอร์ชัน refactor

เปิดสไลด์ประกอบสัปดาห์ 4 →

1. ผลการทดสอบอัตโนมัติ (Automated Test Execution)

ชุดทดสอบหลัก test_app.py ที่พัฒนาโดย QA (เอกพันธ์) มุ่งเน้นการทดสอบพฤติกรรมหลักของ InventoryManager และ Product โดยผลการรันทดสอบบนเครื่องและการบันทึกลง test.json พบว่าผ่าน 100% (5 passed):

Test Case พฤติกรรมที่ทดสอบ ผลลัพธ์
test_add_or_update_product ทดสอบการเพิ่มสินค้าใหม่และการแก้ไขสินค้าเดิม ตรวจสอบชื่อ ปริมาณ และราคา PASSED
test_cut_stock_success ทดสอบการหักสต็อกเมื่อสินค้ามีเพียงพอ (Happy Path) PASSED
test_cut_stock_not_enough ทดสอบการตัดสต็อกเกินจำนวนคงเหลือ (ป้องกันข้อผิดพลาดค่าติดลบ) PASSED
test_cut_stock_not_found ทดสอบการตัดสต็อกสินค้าที่ไม่มีอยู่ในระบบ (Key Error Prevention) PASSED
test_get_total_inventory_value ทดสอบการคำนวณมูลค่ารวมคลังสินค้า ($\sum \text{qty} \times \text{price}$) PASSED

2. รายงานผลการทดสอบเชิงโครงสร้าง (test.json)

เพื่อตอบสนองต่อข้อกำหนดใน Definition of Done (DoD) ระบบทดสอบอัตโนมัติถูกตั้งค่าให้ออกรายงานผลการรันในรูปแบบ JSON เพื่อให้สามารถส่งต่อหรือผสานเข้ากับระบบ CI/CD ได้โดยสะดวก:

{
  "timestamp": "2026-08-10T14:30:00",
  "test_framework": "pytest",
  "total_tests": 5,
  "passed": 5,
  "failed": 0,
  "status": "GREEN",
  "coverage_target": "InventoryManager & Product Core Logic"
}

3. การตรวจสอบความสอดคล้องของโค้ด (Code Parity Check)

FINDING
จากการตรวจเทียบไฟล์ซอร์สโค้ดในโครงการ พบว่าไฟล์ week-3/app_v2.py, week-4/app.py และ app.py ที่รากของรีพอซิทอรี เป็นไฟล์ที่เหมือนกันทุกไบต์ (Exact Match) ซึ่งแสดงถึงความเสถียรของโค้ดในระยะการ Refactor เบื้องต้นก่อนเริ่มรับ Change Request ในสัปดาห์ถัดๆ ไป
