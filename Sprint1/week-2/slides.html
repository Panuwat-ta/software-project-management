การวิเคราะห์จุดวิกฤต (Dangerous Hotspots)

3 จุดอันตรายที่มีการผูกมัดแน่นและเปราะบางสูง

วิเคราะห์จาก Hotspot.md เพื่อป้องกันไม่ให้การแก้โค้ดส่งผลกระทบลูกโซ่ [ข้อมูลจำลอง]

Hotspot 1: ตัวแปรโกลบอล x

ทุกกิจกรรมรุมอ่านเขียนตรง ไร้สกีมาป้องกัน (ใช้คีย์สั้น n, q, p, c) หากคีย์เปลี่ยนจะเกิด KeyError ทันที และทำให้เขียน Unit Test แยกไม่ได้

Hotspot 2: ฟังก์ชัน main()

Monolithic Core รวม UI (print, input), ตรรกะธุรกิจ และ File I/O ไว้ในฟังก์ชันเดียว ความซับซ้อน CC=14 กิ่งเงื่อนไข 17 กิ่ง เสี่ยงบั๊กข้างเคียง

Hotspot 3: Direct Casting

แปลง int() และ float() ไร้ try-except เมื่อผู้ใช้พิมพ์ผิดแอปจะแครชทันที พร้อมช่องโหว่การใส่จำนวนติดลบเพื่อแอบเพิ่มสต็อกสินค้า

พิมพ์เขียวสถาปัตยกรรม (Architecture Blueprint)

Three-Tier Architecture และการวิวัฒนาการ Schema

แยกส่วนความรับผิดชอบ (Separation of Concerns) ตาม blueprint.md [ข้อมูลจำลอง]

สถาปัตยกรรมแยก 3 เลเยอร์ (Three-Tier)
  • Presentation Layer: คอนโซล CLI รับอินพุต ตรวจสอบ Input Validation และแสดงผลหน้าจอเท่านั้น
  • Domain Layer: คลาส InventoryManager ควบคุมตรรกะตัดสต็อก ตรวจสอบสินค้าคงเหลือ และคำนวณมูลค่า
  • Data Layer: โมเดล Product กำหนดฟิลด์ชัดเจน ควบคุมการแปลง Object และจัดเก็บไฟล์ JSON
Schema Evolution & ข้อเท็จจริงสำคัญ
  • เปลี่ยน JSON Schema จากคีย์สั้น (n, q, p, c) สู่ชื่อเต็ม (name, quantity, price, category)
  • รองรับ Backward Compatibility เพื่อแปลงข้อมูลเก่าอัตโนมัติ ป้องกันข้อมูลสูญหาย
  • ข้อเท็จจริงสำคัญ: SQLite และ Member Discount ในสัปดาห์นี้เป็นเพียงแบบร่าง (Design-Only) ยังไม่ได้ส่งมอบจริง
