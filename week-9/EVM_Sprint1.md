# การวิเคราะห์ EVM (Earned Value Management) — ปิด Sprint 1

> ที่มาของตัวเลข: กรณีศึกษา Sprint 1 ใน ENGSE202 Week 9 — ตั้งเป้า 4 Tasks งบ Task ละ 1,000 บาท ทำเสร็จผ่าน PyTest 3 Tasks จ่ายค่าแรงจริงจาก Log Work บน Jira

## ข้อมูลนำเข้า (Inputs) (บาท)

| ตัวแปร EVM | รายละเอียดเนื้องานและการคำนวณ | มูลค่า |
|---|---|---|
| PV (Planned Value) | ตั้งเป้าทำ 4 Tasks งบประมาณ Task ละ 1,000 บาท | 4,000 THB |
| EV (Earned Value) | ทำเสร็จสมบูรณ์ผ่าน PyTest จำนวน 3 Tasks | 3,000 THB |
| AC (Actual Cost) | จ่ายชั่วโมงค่าแรงจริงจากการกด Log Work บน Jira | 4,200 THB |

วิธีรวบรวมข้อมูล (ตาม Workshop ขั้นตอนที่ 3): PV = รวมงบของการ์ดที่ตั้งเป้าไว้ใน Sprint 1, EV = รวมงบของการ์ดที่ปิด Done สำเร็จจริง, AC = รวมชั่วโมงค่าแรงจริงที่สมาชิกกด Log Work บน Jira

## ผลต่าง (Variances)

| ตัวชี้วัด | สูตรคำนวณ | ผลลัพธ์ | การตีความ |
|---|---|---|---|
| SV (Schedule Variance) | SV = EV − PV = 3,000 − 4,000 | **−1,000 THB (ล่าช้ากว่าแผน )** | SV > 0 เร็วกว่าแผน  / SV = 0 ตามแผน  / SV < 0 ล่าช้ากว่าแผน  |
| CV (Cost Variance) | CV = EV − AC = 3,000 − 4,200 | **−1,200 THB (เกินงบประมาณ )** | CV > 0 ประหยัดงบ  / CV = 0 ตรงตามงบ  / CV < 0 เกินงบประมาณ  |

นิยามตามบทเรียน: PV = งบตามแผน ณ ปัจจุบัน, EV = มูลค่างานที่ทำเสร็จจริง, AC = ชั่วโมงค่าแรงที่จ่ายไปจริง

## สาเหตุหลัก (Root Cause)

พบหนี้ทางเทคนิคซ่อนเร้นใน app_v1.py และเสียเวลาแก้ Merge Conflict ที่ไม่จำเป็น ทำให้ SV และ CV ติดลบ

## แผนแก้ไข (Corrective Plan)

1. **แผนเวลา (SV):** ยกงานที่หลุดไปใส่ใน Sprint 2 และปรับเพิ่ม Buffer Time
2. **แผนงบ (CV):** อนุมัติดึงเงิน −1,200 บาท ออกจาก Contingency Reserve ที่ตั้งไว้ในสัปดาห์ที่ 5
3. **ปิด Sprint 1 ที่ EV = 3,000** ยกงานค้างกลับ Backlog แล้ววางแผน Sprint 2 โดยคุมไม่ให้เกิน Velocity (ดู Sprint_Transition.md)
