Pre-Test ทบทวนก่อนสอบกลางภาค
รายวิชา ENGSE225: วิวัฒนาการซอฟต์แวร์และการบำรุงรักษา (Software Evolution and Maintenance)
คำชี้แจง: ตอบคำถามอัตนัยต่อไปนี้ โดยใช้องค์ความรู้ทางวิศวกรรมซอฟต์แวร์และมาตรฐานสากล (ISO/IEC) ในการอธิบายและวิเคราะห์อย่างมีเหตุผล (ข้อละ 10 คะแนน รวม 50 คะแนน)
ข้อที่ 1: ประเภทการบำรุงรักษาซอฟต์แวร์ และกฎของ Lehman (สัปดาห์ที่ 1 - 2)
จากกรณีศึกษาซอฟต์แวร์คลังสินค้าเดิม (app_v1.py) ที่มีปัญหาการใช้ตัวแปรระดับโลก global x และไม่มีการดักจับข้อผิดพลาด (Input Validation)
1.1 หากทีมงานต้องเข้าไปดำเนินการ 3 กิจกรรมต่อไปนี้ จงจำแนกประเภทการบำรุงรักษาซอฟต์แวร์ตามมาตรฐาน ISO/IEC 14764 ให้ถูกต้อง พร้อมอธิบายเหตุผล:
กิจกรรม ก: การแก้ไขโค้ดเพื่อไม่ให้โปรแกรม Crash เมื่อผู้ใช้กรอกตัวอักษรลงในช่องจำนวนสินค้า
กิจกรรม ข: การเพิ่มระบบคำนวณส่วนลดสมาชิก (Member Discount) ตามความต้องการใหม่ของลูกค้า
กิจกรรม ค: การปรับโครงสร้างโค้ดโดยแยกฟังก์ชัน main() ออกเป็นโมดูลย่อยและเปลี่ยนไปใช้ Repository Pattern โดยที่ผลลัพธ์การทำงานภายนอกยังเหมือนเดิม
1.2 จงอธิบาย กฎของ Lehman (Lehman’s Laws of Software Evolution) ในข้อ Law of Continuing Change และ Law of Increasing Complexity โดยเชื่อมโยงกับสาเหตุที่ทำให้โค้ดคลังสินค้าเดิมตัวนี้ยุ่งเหยิงหากขาดการทำ Refactoring

ข้อที่ 2: Program Comprehension และ Reverse Engineering (สัปดาห์ที่ 2)
ในการทำความเข้าใจซอฟต์แวร์ Legacy ดั้งเดิมที่ขาดเอกสารประกอบ
2.1 Static Analysis คืออะไร? และมีประโยชน์อย่างไรยามที่เราต้องเข้ามารับช่วงดูแลระบบเก่าต่อจากผู้อื่น?
2.2 จงวิเคราะห์ข้อเสียของการใช้ Global State (ตัวแปร global x) ในแง่ของการเกิด Side Effects และส่งผลกระทบต่อระดับ Analyzability และ Modifiability ตามมาตรฐาน ISO/IEC 25010 อย่างไร?
ข้อที่ 3: Software Configuration Management (SCM) และ GitFlow (สัปดาห์ที่ 3 & 6)
3.1 ทำไมการปล่อยให้นักพัฒนาในทีมรุม Commit และ Push โค้ดเข้าสู่สาขา main โดยตรงในโครงการซอฟต์แวร์เก่า จึงเป็นอันตรายรุนแรง? จงอธิบายโดยอ้างอิงหลักการ Baseline Management ตามมาตรฐาน ISO 10007
3.2 จงอธิบายโครงสร้างสายงานตามแนวทาง GitFlow Architecture (การแบ่งหน้าที่ของ main, develop, และ feature/ branches) พร้อมระบุว่า การตั้งค่า Branch Protection Rules (เช่น การบังคับ Pull Request และการกำหนด Require Approvers) ช่วยป้องกันไม่ให้โค้ดที่มีบั๊กหลุดเข้าสู่คลังหลักได้อย่างไร?

ข้อที่ 4: Automated Testing และ Regression Testing (สัปดาห์ที่ 3 & 7)
4.1 Regression Testing มีบทบาทสำคัญอย่างไรในการทำวิวัฒนาการซอฟต์แวร์ (Software Evolution)? เหตุใดการทำ Regression Testing ในงานบำรุงรักษาจึงควรเป็นแบบ Automated Testing (เช่น การใช้ PyTest) มากกว่าการใช้คนทดสอบด้วยมือ (Manual Testing)?
4.2 จงอธิบายหลักการทำงานของ Continuous Integration (CI/CD Pipeline) ผ่าน GitHub Actions เมื่อนักพัฒนาทำการเปิด Pull Request (PR) โดยระบุว่าเหตุใดระบบจึงควรล็อกปุ่ม Merge โดยอัตโนมัติหากสคริปต์ PyTest รันไม่ผ่านไฟเขียว?
ข้อที่ 5: Software Quality Metrics และการประเมิน ISO/IEC 14598 (สัปดาห์ที่ 5 - 7)
5.1 ในการประเมินคุณภาพสถาปัตยกรรมใหม่ (To-Be Architecture) ตามมาตรฐาน ISO/IEC 14598 จงอธิบายความหมายและแนวทางในการปรับปรุงค่าดัชนีชี้วัดเชิงเทคนิค (Code Metrics) ต่อไปนี้ให้ดียิ่งขึ้น:
Cyclomatic Complexity (v(G)): คือค่าอะไร? โค้ดที่มีค่า v(G) สูงเกินไปส่งผลเสียอย่างไร และเราสามารถลดค่านี้ได้อย่างไร?
Coupling Between Objects (CBO) & High Cohesion: ทำไมสถาปัตยกรรมที่ดีจึงต้องมุ่งเป้าไปที่ "Low Coupling, High Cohesion"?
5.2 จงเปรียบเทียบความแตกต่างระหว่างกระบวนการ Verification และ Validation (V&V) ในงานบำรุงรักษาซอฟต์แวร์ พร้อมยกตัวอย่างสถานการณ์ที่ซอฟต์แวร์ผ่าน Verification แต่ตก Validation
