Project Initiating Process Group
จุดเริ่มต้นของความสำเร็จในการบริหารโครงการตามมาตรฐานสากล (PMBOK/ISO)

การกำหนดทิศทาง
กระบวนการเริ่มต้น (Initiating) คือการขออนุมัติอย่างเป็นทางการ เพื่อยืนยันว่าโครงการมีคุณค่าเพียงพอที่จะลงทุน ทั้งในด้านเวลา งบประมาณ และทรัพยากรบุคคล
การสร้างความเห็นพ้อง
เป็นช่วงเวลาในการระบุผู้มีส่วนได้ส่วนเสีย (Stakeholders) และทำความเข้าใจความคาดหวัง เพื่อป้องกันปัญหาความเข้าใจไม่ตรงกันในภายหลัง
ความสำคัญของกระบวนการเริ่มต้น

First Step: ก่อนการวางแผน (Planning) จะเริ่มได้ เราต้องมีคำสั่งเปิดโครงการที่ชัดเจน
Alignment: เชื่อมโยงเป้าหมายทางธุรกิจ เข้ากับทีมพัฒนาทางเทคนิค
Gatekeeper: ทำหน้าที่เป็นประตูกลั่นกรองโครงการที่ไม่มีความชัดเจนออกไป
Initiation ในวงจรชีวิตโครงการ

Project Charter: กฎบัตรโครงการ

สัญญาประชาคมของทีม
คือเอกสารสิทธิ์ที่ประกาศว่าโครงการนี้มีตัวตนอยู่จริง โดยระบุวัตถุประสงค์ ขอบเขต และผู้มีอำนาจตัดสินใจไว้อย่างชัดเจน เปรียบเสมือน "รัฐธรรมนูญ" ของโครงการที่ทุกคนต้องยอมรับร่วมกัน
Project Charter คืออะไร?

Objectives
เป้าหมายที่วัดผลได้ของโครงการคืออะไร? เราทำสิ่งนี้ไปเพื่ออะไร?
Authority
ใครคือ Project Manager? และเขามีอำนาจในการจัดการทรัพยากรแค่ไหน?
Constraints
ข้อจำกัดด้านงบประมาณ เวลา หรือเทคโนโลยีที่ต้องปฏิบัติตาม
องค์ประกอบหลักที่ต้องมี

Greenfield (โครงการใหม่)
เริ่มจากศูนย์ พื้นที่ว่างเปล่า ความเสี่ยงคือ "ความไม่แน่นอนของความต้องการ"
Brownfield (วิวัฒนาการซอฟต์แวร์)
เริ่มจากของเดิมที่มีอยู่ ความเสี่ยงคือ "การกระทบระบบเดิม (Side Effects)"
*เหมือนการซ่อมบ้านที่คนยังอาศัยอยู่ ต้องระวังไม่ให้โครงสร้างเดิมพัง
Greenfield vs. Brownfield

In-class Hands-on Activity
กิจกรรม: "Forming the DevTeam & Project Charter Drafting":
ให้นักศึกษาตกลงแบ่งบทบาทภายในกลุ่ม (เช่น Project Manager, Tech Lead, QA/Tester, Developer)
ร่วมกันเขียน Project Charter (กฎบัตรโครงการ) สำหรับการพิจารณาปรับปรุงและบำรุงรักษาซอฟต์แวร์ตัวที่ได้จากวิชา ENGSE225 โดยหัวข้อหลักต้องประกอบด้วย:
Project Objectives: เป้าหมายหลักของการบำรุงรักษาและพัฒนาต่อยอดในเทอมนี้คืออะไร
High-level Scope: ขอบเขตคร่าวๆ (เราจะแก้จุดไหน และจุดไหนที่เราจะไม่แตะต้องเด็ดขาด)
Key Deliverables: ผลลัพธ์ที่จะส่งมอบตอนสิ้นเทอม (เช่น ซอฟต์แวร์เวอร์ชันปรับปรุงที่ไม่มีบั๊กเดิม, เอกสารสถาปัตยกรรมระบบใหม่)
Initial Risks: การระบุความเสี่ยงเบื้องต้นจากการเข้าไปคลุกคลีกับโค้ดเก่า

Team Setup: แบ่งบทบาท PM, Tech Lead, Dev, QA ให้ชัดเจน
Drafting Charter: เขียนกฎบัตรโครงการโดยเน้นเป้าหมายการปรับปรุงระบบเดิม
Tooling: ติดตั้ง Jira หรือ Trello เพื่อเริ่มแตก Task งาน
