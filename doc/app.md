# เอกสารอธิบายการทำงานของระบบคลังสินค้า (Inventory System v2.0)

**ไฟล์อ้างอิง:** `week-3/app_v2.py`

ไฟล์ `app_v2.py` คือเวอร์ชันที่ได้รับการ Refactor (ปรับปรุงโครงสร้างโค้ด) มาจากระบบดั้งเดิมในสัปดาห์ที่ 1 โดยนำข้อบกพร่องที่พบจากการวิเคราะห์มาแก้ไขทั้งหมด เพื่อให้ระบบมีความเสถียร ปลอดภัย และดูแลรักษาได้ง่ายขึ้นในอนาคต

---

## 1. โครงสร้างสถาปัตยกรรมแบบ OOP (Object-Oriented Programming)
โค้ดเวอร์ชันนี้ถูกแบ่งออกเป็น 3 คลาส (Class) หลักอย่างชัดเจน เพื่อแยกตรรกะการทำงาน (Business Logic) ออกจากส่วนแสดงผล (Presentation Layer) ตามหลักการ MVC (Model-View-Controller) ย่อส่วน:

### 1.1 `Product` (ส่วนข้อมูล / Model)
*   ทำหน้าที่เป็นตัวแทน (Object) ของสินค้าแต่ละชิ้น
*   มีฟิลด์ข้อมูลสำคัญ ได้แก่ `item_id`, `name`, `qty` (จำนวน), `price` (ราคา), `remaining` (จำนวนคงเหลือ)
*   **ประโยชน์:** ช่วยให้สามารถจัดการโครงสร้างข้อมูลได้ง่ายขึ้น และป้องกันการส่งค่าผิดพลาดระหว่างฟังก์ชัน

### 1.2 `InventoryManager` (ส่วนตรรกะ / Controller)
*   เป็นหัวใจหลักของระบบ ทำหน้าที่จัดการข้อมูลทุกอย่าง ไม่ว่าจะเป็นการ ดึงข้อมูล เพิ่ม/แก้ไข ตัดสต็อก และคำนวณยอดรวม
*   **ฟังก์ชันที่สำคัญ:**
    *   `add_or_update_product()`: ค้นหาว่ามีสินค้า ID นี้หรือไม่ ถ้ามีให้เขียนทับ ถ้าไม่มีให้สร้างใหม่
    *   `cut_stock()`: หักจำนวนสินค้า (ตรวจสอบว่าของพอตัดหรือไม่ก่อนเสมอ)
    *   `get_inventory_summary()`: คำนวณมูลค่ารวมของคลังสินค้า (จำนวน x ราคา) และเช็คสินค้าที่เหลือน้อยกว่า 10 ชิ้น
    *   `_save_db()`: เซฟข้อมูลลงไฟล์ (Private Method)

### 1.3 `InventoryCLI` (ส่วนแสดงผล / View)
*   จัดการเฉพาะเรื่องของการรับค่า (Input) จากผู้ใช้และการแสดงผลออกหน้าจอ (Print) เท่านั้น
*   รับคำสั่งจากผู้ใช้ นำส่งต่อให้ `InventoryManager` ดำเนินการ และรับผลลัพธ์กลับมาแสดงผล
*   **ประโยชน์:** ถ้าในอนาคตต้องการเปลี่ยนหน้าตาจาก CLI เป็นเว็บแอปพลิเคชัน ก็สามารถทิ้งคลาสนี้และเขียน View ใหม่ได้ทันทีโดยไม่ต้องแตะต้องส่วนของ `InventoryManager`

## 2. ฟีเจอร์ความปลอดภัยที่เพิ่มเข้ามา (Stability & Security)

### 2.1 การป้องกันข้อผิดพลาดจากการกรอกข้อมูล (Input Validation)
*   ใช้บล็อกคำสั่ง `try...except ValueError` ดักจับกรณีที่ผู้ใช้เผลอกรอกตัวหนังสือ (String) ลงในช่องที่ระบบต้องการตัวเลข (Integer/Float)
*   มีการสร้างเงื่อนไขดักจับ (If-Statement) ไม่ให้ผู้ใช้กรอกจำนวนหรือราคาสินค้าเป็น **"ค่าติดลบ"** เพื่อป้องกันตรรกะทางธุรกิจผิดเพี้ยน

### 2.2 การบันทึกข้อมูลแบบเสถียรภาพสูง (Atomic Save)
*   ในฟังก์ชัน `_save_db()` มีการเปลี่ยนวิธีบันทึกไฟล์ JSON ใหม่ เพื่อป้องกันปัญหา "ข้อมูลหาย" หากคอมพิวเตอร์ดับหรือโปรแกรมค้างระหว่างเซฟ
*   **กลไกการทำงาน:** 
    1. ระบบจะเขียนข้อมูลลงไฟล์ชื่อชั่วคราวก่อน (เช่น `data.json.tmp`)
    2. ถ้าเขียนสำเร็จครบถ้วน จึงใช้คำสั่ง `os.replace` สลับไฟล์ชั่วคราวทับไฟล์จริง (เช่น `data.json`) 
    3. การทำเช่นนี้ทำให้ไฟล์ `data.json` ไม่เสี่ยงต่อการพัง (Corrupt) ตรงตามมาตรฐาน **Safe Write Implementation**
