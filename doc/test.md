# เอกสารอธิบายการทำงานของสคริปต์ทดสอบระบบ (Automated Test)

**ไฟล์อ้างอิง:** `week-3/test_app1.py`

ไฟล์ `test_app1.py` เป็นสคริปต์ที่ใช้สำหรับทำ Automated Testing เพื่อตรวจสอบความถูกต้องในการทำงานของไฟล์หลัก `app_v2.py` (Inventory System) โดยเปลี่ยนมาใช้เฟรมเวิร์ก **PyTest** ซึ่งมีข้อดีคือเขียนโค้ดได้สั้น อ่านง่าย และสามารถจัดการวงจรการทดสอบ (Setup/Teardown) ได้อย่างมีประสิทธิภาพ

---

## 1. การเตรียมสภาพแวดล้อม (Test Fixture)
ในการทดสอบระบบคลังสินค้า เราไม่ควรทดสอบกับไฟล์ฐานข้อมูลจริงๆ (`data.json`) เพราะอาจทำให้ข้อมูลจริงสูญหายหรือผิดเพี้ยน โค้ดส่วนนี้จึงใช้ `@pytest.fixture` ในการจำลองข้อมูล:

```python
@pytest.fixture
def manager():
    # สร้างไฟล์ชั่วคราว (Temporary File) เป็น JSON เปล่าๆ
    # แทร็กข้อมูลจำลอง (Mock Data) ลงไป เช่น สินค้า A, B, C
    # โหลดเข้า InventoryManager
    yield mgr
    # ลบทิ้งหลังจากการทดสอบเสร็จสิ้น
```
การทำงานแบบ `yield` ช่วยให้แต่ละ Test Case ได้ฐานข้อมูลจำลองชุดใหม่เสมอ ทำให้การทดสอบแต่ละหัวข้อแยกขาดจากกันโดยสิ้นเชิง (Isolated)

---

## 2. กรณีทดสอบ (Test Cases)
การทดสอบแบ่งออกเป็น 5 ฟังก์ชันหลัก ดังนี้:

*   **`test_calculate_inventory_summary`**:
    *   **เป้าหมาย:** ทดสอบฟังก์ชัน `get_inventory_summary()` 
    *   **สิ่งที่ตรวจเช็ค:** ตรวจสอบว่าระบบนับจำนวนประเภทสินค้าถูกต้องหรือไม่ (3 ประเภท), คำนวณมูลค่ารวมคลังสินค้าถูกต้องไหม (3,300 บาท) และสามารถแจ้งเตือนสินค้าที่มีต่ำกว่า 10 ชิ้น (Item C) ได้อย่างถูกต้อง
*   **`test_cut_stock_success`**:
    *   **เป้าหมาย:** ทดสอบฟังก์ชัน `cut_stock()` ในกรณีปกติ
    *   **สิ่งที่ตรวจเช็ค:** ทดลองตัดสต็อกสินค้าที่มีอยู่จริง และตรวจดูว่าจำนวนที่เหลือ (Remaining) ลดลงอย่างถูกต้อง
*   **`test_cut_stock_not_enough`**:
    *   **เป้าหมาย:** ทดสอบการดักจับข้อผิดพลาดเมื่อผู้ใช้สั่งตัดสต็อกมากกว่าของที่มีอยู่
    *   **สิ่งที่ตรวจเช็ค:** ระบบจะต้องไม่หักสต็อก และต้องส่งข้อความแจ้งเตือน "Error: Not enough stock!"
*   **`test_cut_stock_not_found`**:
    *   **เป้าหมาย:** ทดสอบการตัดสต็อกด้วย ID สินค้าที่ไม่มีอยู่ในระบบ
    *   **สิ่งที่ตรวจเช็ค:** ระบบจะต้องปฏิเสธการตัดสต็อก และแจ้งเตือน "Product not found!"
*   **`test_add_or_update_product`**:
    *   **เป้าหมาย:** ทดสอบฟังก์ชัน `add_or_update_product()`
    *   **สิ่งที่ตรวจเช็ค:** ทดลองเพิ่มสินค้าชิ้นใหม่และตรวจสอบว่าบันทึกลงระบบจริง จากนั้นลองอัปเดตข้อมูลสินค้าเดิม (แก้ชื่อ, จำนวน) เพื่อดูว่าระบบทำการเขียนทับแทนการสร้างใหม่หรือไม่

## 3. ระบบเซฟผลลัพธ์เป็น JSON (Custom Plugin)
โจทย์กำหนดให้การรันทดสอบต้องสามารถแสดงผลทางหน้าจอและเซฟเก็บลงไฟล์ `.json` ได้ สคริปต์นี้จึงได้มีการสร้างคลาส `JSONReportPlugin` ขึ้นมาเพื่อเชื่อมต่อ (Hook) เข้ากับระบบของ PyTest:

*   **`pytest_runtest_makereport`**: ทำหน้าที่ดักจับผลลัพธ์ระหว่างทางของแต่ละ Test Case ว่าได้ผลลัพธ์เป็น PASS (ผ่าน), FAIL (ไม่ผ่าน) หรือ ERROR
*   **`pytest_sessionfinish`**: เมื่อการทดสอบทั้งหมดสิ้นสุดลง ปลั๊กอินจะทำการรวบรวมข้อมูลสรุป (จำนวนเทสทั้งหมด, จำนวนที่ผ่าน, จำนวนที่ตก) มาแปลงให้อยู่ในฟอร์แมตโครงสร้าง Dictionary และเขียนบันทึกลงไฟล์ `week-3/test.json` โดยอัตโนมัติ

## 4. วิธีการรัน
สามารถรันสคริปต์นี้ได้ง่ายๆ ผ่าน Command Prompt (CMD) หรือ Terminal ด้วยคำสั่ง:

```bash
python test_app1.py
```

เมื่อรันคำสั่ง ระบบจะเรียกใช้งาน PyTest ในโหมด Verbose (`-v`) เพื่อแสดงชื่อเทส, ผลลัพธ์สีเขียว/แดง และสร้างไฟล์ `test.json` ให้อย่างสมบูรณ์
