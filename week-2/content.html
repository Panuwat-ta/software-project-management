Week 2 · Design

Evolution & Refactoring Design

ออกแบบ Data Flow Diagram (DFD) ใหม่ เตรียมแผนสำหรับฐานข้อมูล และออกแบบสถาปัตยกรรมระบบสมาชิก

1. การจัดการฐานข้อมูลสมาชิก (Member Integration)

Data Separation
แยกไฟล์จัดเก็บข้อมูลอย่างชัดเจน: data.json สำหรับคลังสินค้า และ members.json สำหรับข้อมูลสมาชิกระบบ
Data Model
กำหนดโครงสร้างข้อมูลสมาชิก เช่น รหัสสมาชิก ชื่อ-นามสกุล และระดับสมาชิก (Tier)
Methodology
สร้างเมธอดเฉพาะสำหรับการเพิ่มสมาชิก ค้นหา และบันทึกข้อมูล (LOAD/SAVE) เพื่อลดความซ้ำซ้อนของการอ่านเขียนไฟล์

2. ปัญหาเชิงสถาปัตยกรรมที่ค้นพบ

  1. Global State (x): การประกาศตัวแปรนอกฟังก์ชัน ทำให้เกิด Tight Coupling การแก้ไขระบบทำได้ยากและสุ่มเสี่ยง
  2. Monolithic Design: UI, Business Logic และ Data Access ปนกันในฟังก์ชันเดียว
  3. Cryptic Naming: ตัวแปร n, q, p ทำให้อ่านและทำความเข้าใจยาก
  4. Risk of Data Corruption: การเซฟทับไฟล์ดั้งเดิม หากเกิดแครชกลางคันจะทำให้ฐานข้อมูลว่างเปล่า (Empty File)

3. สถาปัตยกรรมใหม่ (Proposed Architecture - MVC)

แบ่งเลเยอร์ตามหลักการ Separation of Concerns เพื่อรองรับระบบส่วนลดและจัดการข้อผิดพลาด:

  • Presentation (CLI View): รับ Input จากผู้ใช้งาน, ทำ String Validation, ดักจับ Value Error ล่วงหน้า และแสดงผลลัพธ์ผ่านหน้าจอ
  • Business Logic (Controllers): InventoryManager และ MemberManager ซึ่งทำหน้าที่ตรวจสอบเงื่อนไขสินค้าคงคลัง คิดคำนวณส่วนลด และแก้ไขสถานะข้อมูลภายใน Memory
  • Data Access (Storage Model): Storage Class จัดการเรื่องการเซฟไฟล์ด้วยเทคนิค Safe Atomic Write (เขียนข้อมูลลงไฟล์สำรองก่อนย้ายไปทับไฟล์จริง) ป้องกัน Data Corruption

4. แผนภาพข้อมูลระดับบริบท (DFD Level 1)

ภาพรวมเส้นทางของข้อมูลเมื่อโหลดและบันทึกหลัง Refactor

User -> (CLI Request) -> Controller 
Controller -> (Verify/Calculate) -> In-Memory Store
In-Memory Store -> (Trigger Save) -> Safe Atomic Writer
Safe Atomic Writer -> Temp File -> JSON File (Disk)
