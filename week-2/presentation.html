Week 2

Evolution & Refactoring Design

ออกแบบสถาปัตยกรรมใหม่ และประเมินความเสี่ยง

ออกแบบ Data Flow Diagram (DFD) ใหม่ เตรียมฐานข้อมูลสมาชิก
และปรับโครงสร้างด้วย Separation of Concerns (SoC)

1. โครงสร้างสถาปัตยกรรมใหม่ (MVC Architecture)

Presentation Layer

ส่วนรับ Input (CLI) ดักจับข้อผิดพลาด (Validation) และแสดงผล (View)

Business Logic Layer

ส่วน Controller (InventoryManager, MemberManager) จัดการเงื่อนไขและส่วนลด

Data Access Layer

ส่วน Storage และ Models แยกอ่านเขียนไฟล์ JSON โดยเฉพาะ

Database Separation

แยกไฟล์ data.json (สินค้า) และ members.json (สมาชิก)

2. การเปลี่ยนแปลงการจัดการสถานะ (State Management)

โครงสร้างแบบเดิม (As-is)โครงสร้างแบบใหม่ (To-be)
ใช้ global x ทุกฟังก์ชันใช้ In-Memory Dictionary ภายใน Class
โหลดข้อมูลใหม่ทุกครั้งโหลดครั้งเดียวตอนเปิด (Init) ลด I/O Overhead
รับและเขียนไฟล์ตรงจุดที่เกิด Eventเขียนรวมกัน (Consolidated Save) ป้องกันไฟล์เสียหาย

3. ระบบจัดการฐานข้อมูลสมาชิก (Member Integration)

Member Model

  • รหัสสมาชิก: Member ID
  • ข้อมูลทั่วไป: ชื่อ, นามสกุล
  • ระดับสมาชิก (Tier): Regular, Silver, Gold, Platinum

Member Methods

  • add_member(): สร้างสมาชิกใหม่
  • find_member(): ค้นหาและคืนค่าข้อมูล
  • safe_save(): บันทึกโดยไม่ให้ไฟล์เดิมเสียหาย
