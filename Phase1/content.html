Phase 1 · Project Proposal

Integrated Planning Proposal

ข้อเสนอโครงการฉบับสมบูรณ์ สำหรับปรับปรุงและบำรุงรักษาซอฟต์แวร์ CLI Inventory Management System โดยมุ่งเน้นที่เสถียรภาพ การวางโครงสร้างโค้ด และระบบทดสอบอัตโนมัติ

1. เป้าหมายโครงการ (Project Objectives)

Stability Improvement
ปรับปรุงเสถียรภาพการทำงาน ทำให้ระบบจัดการสินค้ามีความทนทานต่อข้อผิดพลาด (Fault Tolerance) ไม่หยุดทำงานหรือพังลงจากการรับข้อมูลนำเข้าที่ไม่ถูกต้อง (Crash Prevention)
Refactoring
ทำความสะอาดโค้ดเดิม ยุบโค้ดส่วนที่ซ้ำซ้อน แยกฟังก์ชันออกเป็นโมดูล (Modularized) ให้ชัดเจนด้วย OOP/MVC
Data Integrity
ปรับปรุงฟังก์ชันการบันทึกฐานข้อมูล JSON ให้ปลอดภัย ป้องกันความเสี่ยงจากข้อมูลสูญหายด้วยวิธี Safe Atomic Write
Automated Testing
จัดทำชุดทดสอบ (PyTest) เพื่อให้มั่นใจว่าการปรับปรุงโค้ดเดิมจะไม่ส่งผลเสียต่อการทำงานที่มีอยู่ (Regression Testing)

2. ขอบเขตการทำงาน (Final Scope - WBS)

  1. เฟส 1: การวางรากฐานและจัดโครงสร้างสถาปัตยกรรม (Refactoring & Infrastructure)
    - แยกไฟล์ฐานข้อมูลเป็น members.json และ data.json
    - เปลี่ยนไปใช้ Class (InventoryManager, MemberManager)
  2. เฟส 2: การจัดการฐานข้อมูลสมาชิก (Member Database Integration)
    - สร้างเมธอดสำหรับเพิ่ม ค้นหา บันทึกข้อมูลสมาชิก และใช้ Safe Atomic Write
  3. เฟส 3: ปรับปรุงตรรกะการคำนวณ (Discount & Checkout Engine)
    - พัฒนาระบบรับข้อมูลการจ่ายยอด ตรรกะคำนวณส่วนลด และแสดงผลก่อนหักสต็อก
  4. เฟส 4: เพิ่มระบบดักข้อผิดพลาดเชิงลึกและทดสอบ (Exception Handling & QA)
    - ดักจับประเภทข้อมูลนำเข้า ทำ Graceful Degradation และเขียน Unit Tests ครอบคลุมเคสต่างๆ

4. ตารางวิเคราะห์ความเสี่ยงและแผนรับมือ (Risk Matrix & Mitigation)

Global State Conflict
Risk: การประกาศตัวแปรระดับ global อาจทำให้เขียนทับข้อมูลโดยไม่ได้ตั้งใจ
Mitigation: แปลงระบบเป็น OOP แยก Business Logic ออกจาก Presentation Layer (CLI)
Data Corruption
Risk: เขียนทับไฟล์ตรงๆ หากแอปล่มข้อมูลจะหาย
Mitigation: ใช้กระบวนการ Safe Save (Atomic Write) บันทึกผ่าน Temporary Files ก่อนเขียนทับ
Input Type Mismatch
Risk: ผู้ใช้กรอกตัวอักษรแทนตัวเลขทำให้เกิด ValueError และระบบล่ม
Mitigation: บังคับใช้ Input Validation ดักจับด้วย try-except เสมอ
Encoding Risk
Risk: อ่านไฟล์โดยไม่ระบุ encoding อาจทำให้ภาษาไทยเพี้ยนใน OS อื่น
Mitigation: กำหนด encoding='utf-8' เป็นมาตรฐานการอ่าน/เขียนไฟล์ทุกครั้ง

5. DFD Level 1 (Data Flow)

โครงสร้างกระแสข้อมูลที่ออกแบบใหม่เพื่อจัดการสถานะอย่างปลอดภัย

User -> P3: add_update -> Memory Store -> P6: save -> Disk
User -> P4: cut_stock -> Memory Store -> P6: save -> Disk

6. Automated Testing (PyTest)

เกราะป้องกันเพื่อรับประกันความเสถียร (Regression Prevention)

def test_cut_stock_not_enough(manager):
    success, msg, rem = manager.cut_stock("2", 15)
    assert success is False
    assert msg == "Error: Not enough stock!"
    assert rem == 10
