2. Defect vs New Scope, Cross-Team & ลงนาม

3. คัดแยก Defect vs New Scope (ENGSE225)

  • UAT Defect (ต้องแก้ก่อน Merge): ระบบทำงานไม่ตรงสเปกเดิม เช่น สต็อก ≤ Reorder Point แต่ไม่แจ้งเตือน → บั๊กวิกฤต รีบแก้บน Branch แก้ไขด่วนก่อน Merge เข้า main
  • New Scope (ห้ามทำสัปดาห์นี้): ผู้ใช้อยากได้ฟังก์ชันเพิ่ม เช่น "อยากให้ส่งอีเมลหาซัพพลายเออร์ด้วย" → บันทึกลง Future Backlog (v3.0)

4. ทดสอบข้ามกลุ่ม (Cross-Team)

  1. กลุ่ม A ส่งมอบระบบให้ตัวแทนกลุ่ม B ทดสอบในฐานะ "ผู้ใช้งานจริง"
  2. ตัวแทนกลุ่ม B ป้อนข้อมูลตาม 3 Scenarios ลงผลอย่างเป็นกลาง (ขจัด Confirmation Bias)

5. CHANGELOG — [2.0.0-evolution] - 2026-08-31

SemVer 2.0.0, ISO/IEC 14764, Keep a Changelog — v1.0.0-baseline → v2.0.0-evolution (เปลี่ยนสถาปัตยกรรมใหญ่ + โมเดลข้อมูลธุรกิจใหม่)

Added

  • Barcode (CR-01): Product.barcode (เริ่มต้น "") รับค่าผ่าน CLI เก็บใน JSON และรายงาน CSV
  • Reorder Alert (CR-02): Product.reorder_point (เริ่มต้น 5), is_low_stock (quantity <= reorder_point), InventoryManager.get_low_stock_alerts()
  • CSV Export (CR-02): CsvReportExporter หัวตาราง ProductID,ProductName,Barcode,Quantity,ReorderPoint,Price + เมนู CLI 5

Changed

  • สู่ Layered Architecture (Repository Pattern): ขยาย to_dict/from_dict ด้วย barcode/reorder_point, จัดเลขเมนู CLI ใหม่ (ออก 5 → 6), เตือนใกล้หมดอ้างอิงจุดสั่งซื้อซ้ำรายสินค้า

Removed

  • ลบตัวแปรสปาเก็ตตี global x (ผ่าตัด Refactoring ป้องกันข้อผิดพลาดอนาคต)

Fixed

  • บั๊กแครชไฟล์ JSON ไร้บาร์โค้ด (BUG-101): from_dict รองรับคีย์สั้นเดิม (n/q/p/c) ค่าเริ่มต้น barcode/reorder_point = ""/5

ISO/IEC 14764 — ครบ 3 มิติ

  • Preventive: ลบ global x สู่ Repository Pattern ป้องกันข้อผิดพลาดอนาคต
  • Corrective: RCA + แก้บั๊ก Legacy Data Schema (BUG-101)
  • Perfective: บาร์โค้ด (CR-01) + CSV (CR-02) ตามความต้องการใหม่
หลักฐานปล่อย: UAT 3 Scenarios 100% (ลงนามครบ), PyTest 25 tests 100% บน main, Tag v2.0.0-evolution (Annotated + Metadata)
