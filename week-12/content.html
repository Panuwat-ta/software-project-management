1. ขอบเขต

การทดสอบยอมรับของผู้ใช้ (UAT) สำหรับระบบสินค้าคงคลัง (week-12/app.py):
ยืนยันฟังก์ชันเดิม (คำนวณมูลค่าคงคลังถูกต้อง 100%) และฟังก์ชันใหม่
Barcode (CR-01), Reorder Alert (CR-02), CSV Export (CR-02)
UAT คือการจำลองวงจรการทำงานจริงของผู้ใช้แบบ End-to-End (ไม่ใช่ทดสอบย่อยระดับฟังก์ชัน)

2. สถานการณ์ทดสอบ (UAT-SC01–SC03 ตามบทเรียน)

ID บทบาทผู้ใช้ ขั้นตอน & ข้อมูลนำเข้า ผลลัพธ์ทางธุรกิจที่คาดหวัง ผลจริง / สถานะ
UAT-SC01 Inventory Manager รับสินค้าเข้าคลัง: เพิ่มสินค้าใหม่ Milk (885) สต็อก 10 ชิ้น Reorder Point = 5 บันทึกข้อมูลเข้าฐานข้อมูลสำเร็จ ไร้ Crash ผ่าน / ไม่ผ่าน
UAT-SC02 Store Cashier ตัดสต็อกขาย: ตัดสต็อกสินค้า Milk ออก 6 ชิ้น (เหลือสต็อก 4 ชิ้น) ระบบขึ้นข้อความแจ้งเตือนสต็อกต่ำทันที (สต็อก ≤ Reorder Point) ผ่าน / ไม่ผ่าน
UAT-SC03 Purchasing Officer รายงาน: เลือกเมนู Export CSV และเปิดไฟล์ผลลัพธ์ใน Microsoft Excel มีคอลัมน์ Barcode และข้อมูลสินค้าสต็อกต่ำถูกต้อง ผ่าน / ไม่ผ่าน

สรุปผลการทดสอบ (Total Scenarios Passed): 100% (3/3) / ไม่ครบ (ระบุหมายเหตุ)

3. การคัดแยกข้อบกพร่องกับขอบเขตงานใหม่ (Defect vs New Scope)

ประเด็นที่พบระหว่าง UAT จะถูกคัดแยกก่อนลงนาม ตามบทเรียน ENGSE225 Week 12:

  • UAT Defect (ข้อบกพร่องจริง — ต้องแก้ก่อน Merge): ระบบทำงานไม่ตรงตามสเปกเดิม
    เช่น สต็อก ≤ Reorder Point แต่ไม่ยอมแจ้งเตือน
    → การจัดการ: เป็นบั๊กวิกฤต ต้องรีบแก้ไขบน Branch แก้ไขด่วนก่อน Merge เข้า main
  • New Scope (ความต้องการใหม่ — ห้ามทำสัปดาห์นี้): ผู้ใช้ทดลองใช้แล้วอยากได้ฟังก์ชันเพิ่มเติม
    เช่น "อยากให้ส่งอีเมลหาซัพพลายเออร์ด้วย"
    → การจัดการ: ห้ามทำในสัปดาห์นี้ ให้บันทึกลง Future Backlog (v3.0)

4. การทดสอบข้ามกลุ่ม (Cross-Team Testing)

เพื่อขจัด Confirmation Bias (ผู้พัฒนามีอคติเชิงบวก หลีกเลี่ยงการป้อนข้อมูลที่ทำให้ระบบตนเองพัง):

  1. กลุ่ม A ส่งมอบระบบคลังสินค้าให้ตัวแทนกลุ่ม B ทดสอบในฐานะ "ผู้ใช้งานจริง"
  2. ตัวแทนกลุ่ม B ป้อนข้อมูลตาม UAT Scenarios ทั้ง 3 ข้อ และลงผลตรวจอย่างเป็นกลาง

[2.0.0-evolution] - 2026-08-31

Added

  • ฟังก์ชันใหม่ Barcode (CR-01): Product.barcode (ค่าเริ่มต้น "") รับค่าผ่านขั้นตอนเพิ่ม/อัปเดตใน CLI รวมอยู่ในการจัดเก็บ JSON และรายงาน CSV
  • ฟังก์ชันใหม่ Reorder Alert (CR-02): Product.reorder_point (ค่าเริ่มต้น 5), is_low_stock (quantity <= reorder_point) และ InventoryManager.get_low_stock_alerts()
  • ฟังก์ชันใหม่ CSV Export (CR-02): CsvReportExporter พร้อมหัวตาราง ProductID,ProductName,Barcode,Quantity,ReorderPoint,Price และเมนู CLI 5 (ส่งออกรายงาน CSV)

Changed

  • เปลี่ยนโครงสร้างสู่ Layered Architecture (Repository Pattern): ขยายสกีมา Product.to_dict / from_dict ด้วย barcode และ reorder_point, จัดเลขเมนู CLI ใหม่ (ทางออกย้ายจาก 5 → 6), คำเตือนสินค้าใกล้หมดอ้างอิงจุดสั่งซื้อซ้ำของแต่ละสินค้า

Removed

  • ลบตัวแปรสปาเก็ตตี global x (ผ่าตัด Refactoring ป้องกันข้อผิดพลาดอนาคต)

Fixed

  • แก้ไขบั๊กแครชเมื่อเจอไฟล์ JSON ไร้บาร์โค้ด (BUG-101): from_dict รองรับคีย์สั้นแบบเดิม (n/q/p/c) และ กำหนดค่าเริ่มต้น barcode/reorder_point ที่ขาดหายเป็น ""/5

ประวัติการบำรุงรักษา (ISO/IEC 14764 — ครบ 3 มิติ)

  • Preventive: ผ่าตัดลบ global x ปรับสถาปัตยกรรมสู่ Repository Pattern เพื่อป้องกันข้อผิดพลาดอนาคต
  • Corrective: สืบสวนรากเหง้าปัญหา (RCA) และแก้ไขบั๊ก Legacy Data Schema (BUG-101)
  • Perfective: พัฒนาฟีเจอร์บาร์โค้ด (CR-01) และระบบออกรายงาน CSV (CR-02) ตามความต้องการใหม่

หลักฐานปล่อย: UAT 3 Scenarios ผ่าน 100% (ลงนามครบ), Full Suite PyTest 25 tests ผ่าน 100% บนสาขา main, Git Tag v2.0.0-evolution (Annotated Tag พร้อมชื่อผู้สร้าง วันเวลา Metadata)
