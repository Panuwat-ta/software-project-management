Exception Handling & QA

ดักจับข้อผิดพลาด ทดสอบคุณภาพ และความปลอดภัย

เขียน Unit Tests เพื่อป้องกันข้อบกพร่องดั้งเดิมกลับมา
และจำลองสภาวะแวดล้อมที่ทำให้ระบบเสียหาย (Regression Prevention)

1. กลไกดักจับข้อผิดพลาด (Exception Handling)

Input Validation

ดัก ValueError เมื่อผู้ใช้กรอกข้อมูลผิดประเภท (เช่น ตัวอักษรแทนตัวเลข)

Edge Case Checks

เช็คจำนวนสินค้าติดลบ หรือค่าว่างก่อนให้ระบบนำไปประมวลผลต่อ

Graceful Degradation

หากฐานข้อมูลไม่สมบูรณ์ ระบบจะรายงานปัญหาก่อนแทนการปิดตัวเองกะทันหัน (Crash)

Safe Atomic Write

เซฟลงไฟล์ temp.json ก่อนย้ายไปแทนที่ data.json ป้องกัน Data Loss

2. ขอบเขตการทดสอบ (Automated Test Coverage)

ชื่อฟังก์ชันทดสอบพฤติกรรมที่ตรวจสอบ (Test Case)
test_cut_stock_successทดสอบหักสต็อกปกติในเงื่อนไขที่สมบูรณ์ (Happy Path)
test_cut_stock_not_enoughทดสอบดักข้อผิดพลาดเมื่อเบิกของเกินจำนวน (Edge Case)
test_cut_stock_not_foundทดสอบตัดสต็อกด้วย ID ที่ไม่มีอยู่จริง (Edge Case)
test_atomic_saveจำลองให้บันทึกไม่สำเร็จ ข้อมูลเดิมต้องยังคงอยู่ (Data Integrity)

3. ตัวอย่างโค้ดการทดสอบ (PyTest Snippet)

def test_cut_stock_not_enough(manager):
    """ทดสอบดัก Error เมื่อสั่งซื้อเยอะกว่าของที่มี"""
    success, msg, remaining = manager.cut_stock("2", 15)
    
    assert success is False
    assert msg == "Error: Not enough stock!"
    assert remaining == 10  # สต็อกเดิมต้องไม่ลด

ผลลัพธ์: ผ่านการทดสอบทั้งหมด (Success Rate 100%) ทำให้มั่นใจว่าความเสี่ยงดั้งเดิมถูกแก้ไขอย่างสมบูรณ์
