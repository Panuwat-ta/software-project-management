# ตารางการสื่อสาร (Communication Matrix) และเกณฑ์ความพร้อม/ความสำเร็จ (DoR/DoD)

เอกสารนี้ใช้กำหนดมาตรฐานการสื่อสารและการทำงานภายในทีมพัฒนา 3 คน เพื่อไม่ให้งานซ้อนทับกัน และควบคุมคุณภาพงานผ่าน Trello และ GitHub

## ตารางการสื่อสาร (Communication Matrix)

| หัวข้อ / วัตถุประสงค์ | ช่องทาง | ความถี่ | ผู้รับฟัง | ผู้รับผิดชอบ (อ้างอิง RACI) |
| :--- | :--- | :--- | :--- | :--- |
| **อัปเดตงานประจำวัน (Standup)** | Discord Voice / กลุ่มแชท | ทุกเย็น (15 นาที) | สมาชิกทุกคนในทีม | **Project Manager** |
| **การแจ้งบั๊ก / ทดสอบไม่ผ่าน** | แจ้งผ่านการ์ดบน Trello | ทันทีที่พบปัญหา | ผู้เขียนโค้ดฟีเจอร์นั้นๆ | **QA / Tester** |
| **ขอ Review Code ก่อน Merge** | ลิงก์ GitHub PR / Discord | เมื่อสร้าง PR เสร็จ | สมาชิกทีมที่เกี่ยวข้อง | **Tech Lead** |
| **ติดตามความคืบหน้าภาพรวม** | Trello Board (`week-1/trello.md`) | อัปเดตตลอดเวลา | สมาชิกทุกคนและอาจารย์ | สมาชิกทุกคน (คนทำบัตร) |

## เกณฑ์ความพร้อมของงาน (Definition of Ready - DoR)

ก่อนที่ **Developer** จะดึงการ์ดงานบน Trello มาลงมือโค้ด งานนั้นต้องมีองค์ประกอบครบถ้วนตามนี้:
- [ ] **มีรายละเอียด (Description)**: การ์ดต้องอธิบายฟีเจอร์ที่ต้องทำชัดเจน เช่น "แปลงโครงสร้างการเซฟจาก JSON เป็น SQLite"
- [ ] **มีการประเมินจุดเสี่ยง (Hotspot)**: ระบุได้ว่างานนี้อาจกระทบส่วนไหน (อ้างอิงจากเอกสาร `Hotspot.md` ของสัปดาห์ที่ 2)
- [ ] **มอบหมายงานชัดเจน**: มีชื่อตำแหน่งระบุไว้ใน RACI Matrix ว่าใครคือ R (Responsible) และใครคือ A (Accountable)
- [ ] **สร้าง Branch สำหรับทำงาน**: มีการแยก Branch ใน GitHub ออกจาก `develop` เรียบร้อยแล้ว

## เกณฑ์ความสำเร็จของงาน (Definition of Done - DoD)

งานเกี่ยวกับการพัฒนาระบบ (เช่น แก้โครงสร้างเป็น OOP) จะถือว่า **เสร็จสมบูรณ์** และย้ายเข้าช่อง Done ได้ ก็ต่อเมื่อ:
- [ ] **ผ่านการตรวจคุณภาพ Code (Code Review)**: **Tech Lead** เป็นผู้ตรวจสอบความสะอาดของโค้ด (PEP 8) และอนุมัติ (Approve) ตัว Pull Request
- [ ] **ผ่านการทดสอบอัตโนมัติ (Automated Tests)**: สคริปต์ `test_app.py` หรือ `test_app1.py` ที่เขียนโดย **QA** ต้องทำงานสำเร็จ 100% ไม่มี Error
- [ ] **รวมโค้ดสำเร็จ**: ระบบถูก Merge เข้าไปในกิ่งหลักเรียบร้อยแล้ว
- [ ] **ทำเอกสารสรุปผล**: มีการทำรายงานการทดสอบ (เช่น `test.json`) หรือแจ้งอัปเดตใน Trello เรียบร้อย
