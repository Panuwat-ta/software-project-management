# ตัวอย่างการวิเคราะห์ผลต่างงบประมาณ (Cost Variance Analysis)

เอกสารฉบับนี้ใช้ควบคุมโครงการ (Project Control) โดยอ้างอิงจากหลักการ Earned Value Management (EVM) เพื่อติดตามการใช้ทรัพยากรบุคคลและต้นทุนแฝงในการทำงานของทีมพัฒนา

## สูตรคำนวณ EVM
- **ผลต่างงบประมาณ (Cost Variance - CV)** = มูลค่างานที่ทำเสร็จ (Earned Value - EV) - ต้นทุนจริง (Actual Cost - AC)
- **ตัวชี้วัดสถานะ**:
  - `CV > 0`:  ต่ำกว่างบประมาณที่ตั้งไว้ (Under Budget)
  - `CV = 0`:  ตรงตามงบประมาณ (On Budget)
  - `CV < 0`:  เกินงบประมาณ (Over Budget)

## กรณีศึกษา: งานย้ายฐานข้อมูล JSON ไป SQLite

| รายการชี้วัด | คำอธิบาย | มูลค่าคำนวณ (บาท) |
| :--- | :--- | :--- |
| **งบประมาณที่ตั้งไว้ (Planned Cost/Budget)** | ตั้งเป้าให้ **Developer** ใช้เวลา 6 ชม. (อัตราค่าแรงสมมติ 400 บาท/ชม.) | 2,400 บาท |
| **มูลค่างานที่ทำเสร็จ (Earned Value - EV)** | งานถูกโอนย้ายฐานข้อมูลและผ่านการเทสต์จาก **QA** เรียบร้อย (เสร็จ 100%) | 2,400 บาท |
| **ต้นทุนจริง (Actual Cost - AC)** | Developer พบปัญหาโครงสร้างข้อมูลเก่า (JSON) ไม่เข้ากับ SQLite ทำให้ต้องเสียเวลาแก้บั๊กเพิ่มรวมเป็น 10 ชม. (10 * 400) | 4,000 บาท |

### วิธีคำนวณ

$$ CV = EV - AC $$
$$ CV = 2,400 - 4,000 = -1,600 $$

**ผลลัพธ์**: **-1,600 บาท** ( เกินงบประมาณ)

### แนวทางบริหารจัดการปัญหา (Management Action)
เนื่องจากงานนี้ใช้งบเกินเป้าถึง 1,600 บาท ในฐานะ **Project Manager** จะต้อง:
1. **แจ้งเตือนความเสี่ยง (Warning)** ให้ทีมทราบ
2. **จัดการงบสำรอง (Contingency Reserve)**: ต้องดึงเงินจากงบสำรองที่ตั้งไว้ 15% ของโครงการมาชดเชยทันที
3. **ปรับการทำงาน**: ปรึกษาหารือกับ **Tech Lead** เพื่อทบทวนการออกแบบ (Blueprint) ให้ละเอียดขึ้นก่อนเริ่มเขียนโค้ดในระบบ Member System ต่อไป เพื่อป้องกันปัญหาการแก้โค้ดซ้ำซ้อนในอนาคต
