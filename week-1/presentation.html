Week 1

Planning & Legacy Code Review

ขั้นวางแผนและทบทวนโค้ดดั้งเดิม

วิเคราะห์โครงสร้างโปรแกรมเดิมที่เป็น Monolithic JSON-based
ร่าง Project Charter และ Scope การทำงาน

1. กฎบัตรโครงการ (Project Charter)

👥 ทีมงานและบทบาท

  • PM / Developer: ภานุวัฒน์ - วิเคราะห์ระบบ, เขียนโค้ดหลัก
  • Tech Lead: ณฐภาพ - ตรวจรับงาน, ออกแบบ Architecture
  • QA / Tester: เอกพันธ์ - เขียน Unit Tests (PyTest)

🎯 เป้าหมายหลัก (Objectives)

  • Stability: ปรับปรุงให้ทนทานต่อข้อผิดพลาด (Fault Tolerance)
  • Refactoring: ยุบโค้ดซ้ำซ้อน แยกโมดูลให้ชัดเจน (MVC)
  • Testing: สร้าง Automated Tests ป้องกัน Regression

2. โค้ดดั้งเดิม (Legacy Code) และปัญหา

ระบบเดิมเป็น CLI แบบ Monolithic และใช้ไฟล์ JSON ผูกกับตัวแปร Global

ปัญหาที่พบ (Code Smells)ผลกระทบที่มีต่อระบบ
ใช้ global x ในทุกฟังก์ชันเสี่ยงค่าขัดแย้งกัน ทำ Unit Test ยาก
ใช้ json.dump() ตรงๆหากไฟดับกลางคัน ข้อมูลหาย (Data Corruption)
ไม่มี Input Validationผู้ใช้พิมพ์ตัวอักษรแทนตัวเลข โปรแกรมจะ Error ทันที
ตรรกะกองรวมกัน (Monolithic)การแก้ไขส่วนใดส่วนหนึ่งอาจกระทบส่วนอื่นได้ง่าย

3. ขอบเขตการทำงาน (Final Scope - WBS)

✅ In-Scope (สิ่งที่ทำ)

  • เฟส 1: Refactoring & Infrastructure (OOP, แยกไฟล์)
  • เฟส 2: Member Database Integration
  • เฟส 3: Discount & Checkout Engine
  • เฟส 4: Exception Handling & Automated Tests (PyTest)

❌ Out-of-Scope (สิ่งที่ไม่ทำ)

  • ไม่มีการพัฒนาหน้าต่าง GUI (คงรูปแบบ CLI ไว้)
  • ไม่เชื่อมต่อระบบฐานข้อมูล SQL ภายนอก (ยังใช้ Local File)
  • ไม่ทำระบบซื้อขายเต็มรูปแบบนอกเหนือจากการทดสอบของระบบย่อย

4. ความเสี่ยงและแนวทางรับมือ (Risk Mitigation)

ความเสี่ยงหลัก (Critical Risk)แนวทางป้องกัน (Mitigation)
Global State Conflictแปลงระบบเป็น OOP แยกเป็น Manager Classes
Data Corruption ตอนเซฟใช้ Safe Atomic Write ผ่าน Temp File
Input Type Mismatch (ValueError)ดักจับด้วย try-except ล่วงหน้าก่อนเข้า Business Logic
Encoding Risk (ภาษาไทยเพี้ยน)บังคับ encoding='utf-8' ทุกครั้งที่มีการ I/O
