Week 1 · Review

Planning & Legacy Code Review

สรุปผลการวิเคราะห์โครงสร้างโค้ดเดิม การจัดทำ Project Charter และกำหนดขอบเขตของการพัฒนา

1. วิเคราะห์ระบบเดิม (Legacy Code Review)

Global State
ระบบเดิมใช้ตัวแปร global x ในการเก็บข้อมูลคลังสินค้า ทำให้เกิดความเสี่ยง (Global State Conflict) เมื่อมีการประมวลผลซ้อนกัน
Data Storage
ใช้ json.dump() บันทึกไฟล์ทับทันที หากเกิดข้อผิดพลาดระหว่างรัน (เช่น ไฟดับ) ข้อมูลสูญหายทั้งหมด
Input Handling
ระบบไม่ตรวจสอบประเภทของข้อมูล (No Input Validation) หากผู้ใช้กรอกตัวอักษรลงในช่องตัวเลข โปรแกรมจะแครช (ValueError)

2. เป้าหมายสัปดาห์ที่ 1

  1. System Understanding: ทำความเข้าใจตรรกะเดิมของฟังก์ชันทั้ง 5 (load, add, show, cut_stock, check)
  2. Project Charter: กำหนดเป้าหมายหลักในการแก้ปัญหาระบบเดิม (เน้นเสถียรภาพ)
  3. Scope Definition: ตัดสินใจแบ่งงานเป็น 4 เฟสหลัก เพื่อค่อยๆ ปรับปรุงโดยไม่กระทบความสามารถเดิมของระบบ

3. ขอบเขตงาน (Final Scope)

In-Scope
Refactoring ให้อยู่ในรูป Object-Oriented (OOP), การเพิ่มฐานข้อมูลสมาชิก (members.json), การเพิ่มตรรกะคำนวณส่วนลด, การป้องกัน Error และทำ Unit Test.
Out-of-Scope
ไม่มีการพัฒนาหน้าต่าง GUI, ไม่มีการใช้ SQL Database ภายนอก (ยังคงใช้ Local JSON/SQLite เพื่อความเรียบง่าย)

4. แผนงานระยะต่อไป

เมื่อได้ปัญหาที่ชัดเจนแล้ว ในสัปดาห์ที่ 2 ทีมจะดำเนินการออกแบบ Data Flow Diagram (DFD) และปรับโครงสร้างการทำงานจาก Global State ให้เป็นรูปแบบ Class (MVC) รวมถึงประเมินความเสี่ยงเชิงระบบอย่างละเอียด
