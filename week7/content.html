Week 7 · Quality & SCM

Quality & SCM

การประเมินคุณภาพซอฟต์แวร์ตามมาตรฐานสากล ISO/IEC 14598 และการสรุปต้นทุนงบประมาณของทีม รวมถึงการคำนวณความสามารถในการผลิต (Capacity Planning) สำหรับ Sprint 1

1. การประเมินคุณภาพด้วย ISO/IEC 14598

เพื่อรับประกันว่าการทำ Refactoring ในครั้งนี้สามารถยกระดับคุณภาพของระบบสินค้าคงคลังได้อย่างแท้จริง ทีมงานได้กำหนดตัวชี้วัดเชิงปริมาณ (Quantitative Metrics) เพื่อประเมินความก้าวหน้า ดังนี้:

Max Cyclomatic Complexity v(G)
เป้าหมายการบำรุงรักษา (Maintainability): ลดความซับซ้อนของลอจิก
ในเวอร์ชันดั้งเดิม (app_v1.py) ฟังก์ชัน main() มีการใช้คำสั่ง if-elif-else ซ้อนกันมากกว่า 20 จุด (v(G) > 20) ทำให้เสี่ยงต่อการเกิดบั๊กแฝง โค้ดเวอร์ชันใหม่ได้แยกย่อยฟังก์ชันออกเป็น Modular ทำให้ค่า v(G) ของแต่ละฟังก์ชันมีค่าไม่เกิน 8 ซึ่งจัดอยู่ในเกณฑ์ความเสี่ยงต่ำและอ่านง่าย
Code Coverage & Testing
เป้าหมายด้านความน่าเชื่อถือ (Reliability):
จากเดิมที่ไม่มีระบบทดสอบอัตโนมัติเลย (Coverage = 0%) สถาปัตยกรรมใหม่ถูกบังคับให้สอดคล้องกับชุดทดสอบ test_app.py ที่ถูกออกแบบครอบคลุม Business Logic หลัก โดยมีเป้าหมายที่ Code Coverage ไม่ต่ำกว่า 85%
Data Security & Global States
เป้าหมายด้านความปลอดภัย:
กำจัดการใช้ Global Variables พร่ำเพรื่อ (เช่น global total_value) โดยนำ Encapsulation มาใช้ผูกตัวแปรไว้ใน Class Instance เพื่อป้องกันการแก้ไขข้อมูลโดยไม่ตั้งใจ นอกจากนี้ เมื่อเชื่อมต่อ SQLite จะมีการบังคับใช้ Parameterized Query ตลอดเวลาเพื่อป้องกัน SQL Injection 100%
CI/CD Quality Gate
ท่อส่งมอบงานอัตโนมัติ:
ติดตั้ง GitHub Actions ผ่านไฟล์ .github/workflows/pytest.yml ทำหน้าที่เป็น "ยามรักษาการณ์" คอยรัน PyTest ทุกครั้งที่มีการขอรวมโค้ด หากทดสอบไม่ผ่าน ปุ่ม Merge จะถูกระงับ เพื่อป้องกันการแพร่กระจายของบั๊กเข้าสู่สภาพแวดล้อมโปรดักชัน

2. ต้นทุนงบประมาณ (Cost Baseline) และ Sprint 1 Planning

เอกสารสรุปแผนการเงินรวมของโครงการและการประเมินขีดความสามารถของทีมทำงาน สำหรับระยะเวลาดำเนินงาน Sprint 1:

การคำนวณกำลังการผลิตของทีม (Team Capacity Calculation)

  • ขนาดของทีม (Team Size): 3 คน (Project Manager, QA/Tester, Tech Lead)
  • เวลาที่สามารถทุ่มเทให้โปรเจคได้ (Availability): 6 ชั่วโมง/คน/สัปดาห์
  • กรอบเวลาของ Sprint (Duration): 2 สัปดาห์
  • สูตรคำนวณความจุรวม (Total Capacity): 3 คน × 6 ชั่วโมง × 2 สัปดาห์ = 36 Man-Hours
  • นัยสำคัญ: ผู้จัดการโครงการไม่สามารถดึงการ์ดงานเข้า Sprint Backlog เกินกว่า 36 ชั่วโมงได้ เพื่อป้องกันการทำงานล่วงเวลา (Overwork) และรักษามาตรฐาน DoD
