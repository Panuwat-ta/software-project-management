✅ Verification ผ่านฉลุย:
โค้ดถูกหลักเกณฑ์โครงสร้างเทคนิค สะอาดสะอ้าน ปราศจากบั๊กและสอดคล้องกับการทดสอบหน่วย

เมื่อซอฟต์แวร์มีอายุยาวนานขึ้น การไม่ทำกระบวนการ V&V อย่างเป็นระบบทำให้ความน่าเชื่อถือของระบบดิ่งลงอย่างรวดเร็ว

Baseline (ฐานข้อมูลคอนฟิกูเรชันอ้างอิง): คือข้อกำหนดหรือชุดชิ้นงานซอฟต์แวร์ที่ได้รับการตรวจสอบ ตรวจทาน และยอมรับเห็นชอบร่วมกันอย่างเป็นทางการในขั้นตอนการทบทวนประเมิน ซึ่งจะถูกนำมาใช้เป็นฐานอ้างอิงและอ้างอิงในการพัฒนาหรือแก้ไขรอบขั้นถัดไป

SOFTWARE CONFIGURATION MANAGEMENT BASELINING BASICS
Software Configuration Baseline คืออะไร?

หากเริ่มเขียนและดัดแปลงโค้ดเก่าทันทีโดยไม่มีการทำ Baseline Audit จะส่งผลกระทบอันตรายอย่างยิ่งต่อโครงการบำรุงรักษา:
ยากในการวินิจฉัยปัญหา: ไม่สามารถแยกแยะได้ว่า บั๊กที่พบเกิดจากโค้ดระบบดั้งเดิมที่มีปัญหาอยู่แล้ว หรือเกิดจากโค้ดใหม่ที่เราเขียนเพิ่มเข้าไป
ขาดจุดถอยร่นฉุกเฉิน: หากระบบล่มรุนแรงจากการแก้ไขสถาปัตยกรรมเดิม จะไม่มีจุดถอยกลับที่การันตีว่าทำงานได้ปลอดภัยร้อยเปอร์เซ็นต์
STRATEGIC QUALITY ASSURANCE BASELINE AUDITING
ทำไมต้องทำ Baseline Audit?

ก่อนที่กลุ่มพัฒนาจะทำการติดป้าย Baseline แฟ้มโค้ดขึ้นระบบ สิ่งสำคัญที่สุดตามหลักสากลคือการทำให้คลังเก็บโค้ด (GitHub Repository) สะอาด มีโครงสร้างสมบูรณ์ ปราศจากสิ่งปนเปื้อน 3 กลุ่มหลัก:
OS Metadata Trash
ไฟล์ขยะระบบปฏิบัติการ: ไฟล์ที่ OS สร้างขึ้นชั่วคราวอย่างอัตโนมัติ เช่น .DS_Store ใน macOS หรือ Thumbs.db ใน Windows
Compiler & Tool Artifacts
ไฟล์ของเครื่องมือรัน: โฟลเดอร์ที่เก็บข้อมูลภายในโปรแกรมทดสอบหรือระบบแปล เช่น .pytest_cache/, __pycache__/ หรือ .idea/
Confidential Secrets
ข้อมูลความปลอดภัย: รหัสผ่านและสิ่งที่เป็นความลับอย่างเคร่งครัน เช่น API Keys, secrets.env หรือไฟล์การตั้งค่าส่วนบุคคล

เกิดข้อขัดแย้งของโค้ดโดยไม่สมเหตุสมผล (Merge Conflicts): การรวบรวมแคชของเพื่อนสองคนที่รันโปรแกรมทดสอบเดียวกันทำให้ไฟล์ระบบตีกันวุ่นวาย เสียเวลาทำงานอย่างมหาศาลโดยไม่จำเป็น

GIT ENGINEERING CONCEPTS RELEASE TAGGING

มาตรฐานสากลที่วิศวกรซอฟต์แวร์ทุกคนต้องใช้คือ MAJOR . MINOR . PATCH (เช่น v1.0.0)
MAJOR
เปลี่ยนเมื่อมีการดัดแปลงโครงสร้างแกนหลักครั้งใหญ่ จนไม่สามารถเอาโค้ดเก่ามาใช้ได้ (Incompatible API Changes)
MINOR
เปลี่ยนเมื่อมีการเพิ่มคุณสมบัติและฟังก์ชันเพิ่มเติมของระบบ แต่ยังสามารถใช้งานร่วมกับแกนหลักเดิมได้ (Backward-Compatible)
PATCH
เปลี่ยนเมื่อแก้ไขบั๊กขนาดเล็กที่ผิดพลาดจากโปรแกรมรอบก่อน โดยทำงานร่วมกับระบบอื่นได้สมบูรณ์ (Backward-Compatible Bug Fixes)
